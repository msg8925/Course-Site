01

The P2P file-sharing model

In a P2P file-sharing network, every node can share and request files at the same time. There's no single point of failure for the file itself — but finding who currently has a file (discovery) can still be a challenge.

GnutellaA historical P2P file-sharing protocol — one of the earliest real examples of this model at scale. Today's practical uses Filius's equivalent file-sharing service.

03

P2P vs client-server: what if a device goes offline?

 P2P file sharingClient-server
One node offlineOther nodes may still have the fileIf it's the server, nobody can access anything
Single point of failure?No single point for the file itselfYes — the server
Watch for thisP2P isn't automatically "better" — if only ONE node ever had a file and it goes offline before anyone else downloads it, that file is gone. Redundancy in P2P depends on the file having actually spread to multiple nodes.
04

Practical lab steps

  1. Build a 3-laptop network connected via a switch.
  2. Configure the file-sharing service on the nodes.
  3. Share a file from one laptop; have another search for and download it.
  4. Slow the simulation speed to observe the request/transfer traffic on the switch.
  5. Add a third laptop mid-transfer and discuss how a P2P network could route around a node going offline, contrasting with what happens if a switch itself fails.
