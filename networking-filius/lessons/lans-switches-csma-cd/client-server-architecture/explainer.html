01

The client-server model

A dedicated server provides a service; clients request it. Web browsing, email, and file servers all work this way.

Compare to Session 5P2P had every node acting as both client and server. Here, the roles are fixed: one machine serves, the rest only request.
 AdvantagesDisadvantages
Client-serverCentralised control, better security, easier backupSingle point of failure, cost, potential bottleneck

04

Practical lab steps

  1. Reuse the Session 5 switch-based network; configure one node as a web server, others as clients.
  2. Have a client send an HTTP request to the server.
  3. Slow the simulation speed right down and step through the packet exchange, identifying the request and response.
  4. Open the data exchange view and interpret the basic contents.
  5. Take the server offline and have a client try again — observe the failure.
