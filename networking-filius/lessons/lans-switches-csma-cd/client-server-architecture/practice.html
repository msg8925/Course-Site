4. What is the main disadvantage of relying on a single server?

It's harder to secure It's a single point of failure It requires more client devices

5. Explain why centralised control makes backups easier in a client-server system.

Reveal model answer
All the important data lives in one known location (the server), so it can be backed up from a single point, rather than needing to gather copies scattered across many independent devices.
C

Comparing to P2P

6. Which model gives distributed rather than centralised control?

Client-server Peer-to-peer

7. Compare fault tolerance between client-server and P2P.

Reveal model answer
Client-server has a single point of failure — if the server goes down, nobody can access the service. P2P has no single point of failure for the data itself, since multiple nodes can hold copies.

8. Give one scenario better suited to P2P than client-server.

Reveal model answer
Sharing large files directly between devices without needing to maintain and pay for a dedicated central server (e.g. distributing a large public file to many users).

E

Exam-style question

11. A company is choosing between a client-server system and a P2P system for internal document sharing. Explain one advantage and one disadvantage of each, and recommend an approach.

Reveal model answer
Client-server advantage: centralised control makes access permissions, backups, and version control straightforward. Client-server disadvantage: if the server fails, nobody can access any documents until it's restored. P2P advantage: no reliance on one central machine staying online. P2P disadvantage: harder to enforce consistent access control and ensure everyone has the latest version. For a company needing reliable, controlled access to shared documents, client-server is usually more appropriate, provided the server is properly maintained and backed up.

12. Explain why the disadvantage demonstrated in the lab (server offline, client request fails) does not apply in the same way to a P2P network.

Reveal model answer
In client-server, only one machine (the server) can fulfil requests, so its failure blocks everyone. In P2P, any node that holds the relevant data can respond to a request, so one node going offline doesn't necessarily prevent others from getting what they need — as long as the data has spread to more than one node.
