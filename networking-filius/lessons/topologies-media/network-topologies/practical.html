PART A

Build and label the star

Build the familiar star topology (a switch with multiple PCs) — the same shape you've used since Session 3. Today, name it: this is a star topology.

How many PCs did you connect to the switch?
PART B

Break one link in the star

Disconnect one PC's cable from the switch (or delete the connection in Filius).

What happens to the disconnected PC? What happens to everyone else?
PART C

Build a bus-style network (if supported)

Check whether Filius's component list includes a hub or shared-segment device you can use to build a bus. If it does, connect several PCs to it. If it doesn't, draw the bus network below instead: one shared cable with 4 PCs tapped into it.

Did your version of Filius support a bus-style build? Describe what you built (or sketched).
PART D

Break the shared cable

Break the shared cable (or reason it through on your diagram if you couldn't build one) partway along its length.

What happens this time, compared with breaking one link in the star?
PART E

Attempt a small mesh

Try connecting 3–4 PCs so that every PC has a direct link to every other PC (a full mesh). If Filius's per-node connection limit stops you scaling past a few devices, build as much of it as you can and reason through the rest with your teacher on a whiteboard.

How many PCs could you connect in full mesh before running out of connections on a node? What did you have to reason through instead of building?
STRETCH

Stretch task

Optional challengeA full mesh of n devices needs n(n−1)/2 direct links. How many links would a full mesh of 10 devices need? Is this practical for a real network of that size?
