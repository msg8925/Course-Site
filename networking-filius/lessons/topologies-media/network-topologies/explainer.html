Same devices, same switch, same cables — but arranged differently. The arrangement decides what happens when one link fails.

01

What is a topology?

A network's topology is the pattern in which its devices are connected — who has a direct link to whom. It's a separate question from what the devices actually do (client-server vs peer-to-peer): topology is about wiring layout, not roles.

Why it mattersThe topology decides two practical things: how much cable you need, and what happens to the rest of the network when one link or one device fails.
02

Star topology

Every device has its own direct link to a central point — almost always a switch. This is exactly what you built in Sessions 3–6, you just haven't named the shape until now.

AdvantagesDisadvantages
One faulty cable or device only knocks out that one device — everyone else keeps workingThe central switch is a single point of failure for the whole network
Easy to add or remove a device — just plug/unplug at the switchNeeds more cable overall than a bus (one run per device)
Easy to spot which cable has failedDepends on the switch having enough ports
03

Bus topology

Every device taps into one shared cable that runs the length of the network, rather than each device getting its own line to a central point. Older bus networks used coaxial cable with a terminator at each end to stop signals reflecting back down the wire.

Mostly historicalBus networks are rare in modern LANs — almost everything built today is switched (star). Filius, like most modern tools, is built around a switch/star model by default, which is itself a sign of how far bus has fallen out of use.
AdvantagesDisadvantages
Uses less cable than a star for a small, simple networkOne break in the shared cable takes the whole segment down
No central device neededOnly one device can transmit at a time without collisions
Simple to set up for a handful of devicesHard to fault-find — you have to check the whole cable run
04

Mesh topology

Every device has a direct link to every other device (a full mesh), or to several others (a partial mesh). There's no single central point at all.

AdvantagesDisadvantages
Extremely fault-tolerant — a link can fail and traffic can often still get through another routeNeeds a huge amount of cable: a full mesh of n devices needs n(n−1)/2 links
No single point of failureAdding one new device means wiring it to every existing device
Can carry more total traffic at once (no shared bottleneck)Expensive and complex to install and maintain at scale
Tooling noteFilius limits how many network connections a single node can have, so a full mesh of more than 3–4 devices usually can't be built directly in the simulator. That's a genuine limit of the tool, not a simplification of the concept — real mesh networks (e.g. some backbone links between data centres) really do use this many physical connections.
05

Break a link: try it

The real test of a topology is what happens when something fails. Pick a topology below, then break a link and see what's still working.

Break-a-link simulator

Pick a topology tab, then try breaking a link.
NoticeIn the star, breaking one link only isolates that one PC. In the bus, breaking the shared cable splits — or takes down — the whole segment. In the mesh, breaking one direct link still leaves another route between those two PCs, via a third device.
06

Choosing a topology

In practice, most modern LANs use star (it's what a switch gives you by default), but the choice still matters when you're weighing up cost, resilience and scale:

  • A school computer lab: star — cheap switches, easy to add machines, one dead cable doesn't stop the lesson.
  • A data centre backbone connecting core routers: often partial mesh — the extra cost of redundant links is worth it, because those links carry huge amounts of traffic and downtime is very expensive.

07

Practical lab steps

  1. Build the familiar star topology (switch + multiple PCs) and label it as "star" for the first time.
  2. Break one link in the star — confirm only that one PC is affected.
  3. If Filius's hub/shared-segment component supports it, build a bus-style network; otherwise, work through it as a diagram.
  4. Break the shared bus cable (or reason it through on the diagram) and compare the result directly with the star.
  5. Attempt a small mesh (3–4 nodes) if Filius's per-node connection limit allows; otherwise build a partial mesh and reason through the rest on a whiteboard.
