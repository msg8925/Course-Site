01

What is peer-to-peer (P2P)?

In a peer-to-peer network, there's no central server. Every device can act as both a client (requesting data) and a server (providing data) at the same time.

Real-world analogyThink of a P2P network like a group of friends lending each other books directly, rather than everyone borrowing from one library.

Today's network is the simplest possible P2P setup: just two PCs, cabled directly together. Later (Session 5) we'll scale this up to a proper file-sharing example with Gnutella.

02

A quick recap: NIC and IP address

From Session 1: every device has an IP address (its identity on this network) and a NIC with a fixed MAC address (its physical hardware identity). Today we find out how one gets linked to the other.

03

ARP, step by step

ARP (Address Resolution Protocol) is what links an IP address to a MAC address on the local network. Your device knows the IP address it wants to reach, but the actual delivery needs the MAC address — that's ARP's job to find out.

Walk through a ping between two PCs

Watch for thisARP resolves addresses on the local network only. Once a router gets involved (Session 11), the process changes.
04

Practical lab steps

  1. Build a 2-PC direct-connected network in Filius.
  2. Run ipconfig on each PC — confirm addressing.
  3. Run arp -a on PC1 before any contact with PC2.
  4. ping PC2 from PC1.
  5. Run arp -a again — what's new, and why?
  6. Repeat in reverse: ping PC1 from PC2, and check PC2's ARP table.
