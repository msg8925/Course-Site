Input and Output Pins Explained

Section focus: Arduino Programming — Lesson 3.2  |  Duration: ~40 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Explain the difference between a digital and an analog pin
  • Explain what pinMode() does and why it's necessary
  • Use digitalWrite() and digitalRead() correctly
  • Identify which of your Arduino's pins can do what, just by reading the board
Real-world analogy: Think of each Arduino pin as a single wall socket that can be configured two different ways: either as a power outlet (an output, sending voltage out to something like an LED), or as a doorbell button (an input, watching for a signal coming in from something like a switch). The same physical pin can do either job — you just have to tell the Arduino which job you want, before you can use it.

1. Digital vs Analog Pins

TypeWhat it senses/producesLabelled on the board as
DigitalOnly two states: HIGH (5V) or LOW (0V)Numbered pins (0, 1, 2, 3...)
Analog inputA range of voltage, read as a number from 0–1023Pins labelled A0–A5

You've already used analog pins in Lesson 3.9 (Potentiometer) with analogRead(). This lesson focuses on the digital pins, which you'll use far more often overall.

What about analog output? Some digital pins, marked with a "~" symbol next to their number, can also simulate an analog-like output using analogWrite() — this is PWM, which you've already used for LED brightness and motor speed. It's technically still a digital pin rapidly switching on and off, not true analog voltage — worth knowing, though the practical usage is what matters most for now.

2. Setting a Pin's Mode

Before using any digital pin, you must tell the Arduino whether it will be an input or an output, using pinMode() inside setup():

void setup() {
    pinMode(7, OUTPUT);  // pin 7 will send signals out
    pinMode(8, INPUT);   // pin 8 will read signals in
}
Skipping pinMode() is a common source of confusing bugs. Arduino pins default to INPUT mode if never set, which means a pin you intended as an output may simply not work as expected until you explicitly configure it. Always set every pin's mode in setup() before using it elsewhere in your code.

3. Writing to an Output Pin

void setup() {
    pinMode(7, OUTPUT);
}

void loop() {
    digitalWrite(7, HIGH);  // pin 7 outputs 5V
    delay(1000);
    digitalWrite(7, LOW);   // pin 7 outputs 0V
    delay(1000);
}

This is the exact same pattern you'll use in the very next lesson to blink an LED — digitalWrite() simply sets a pin HIGH or LOW, and whatever is connected to that pin (an LED, a relay, a motor driver's input) responds accordingly.

4. Reading From an Input Pin

void setup() {
    pinMode(8, INPUT);
    Serial.begin(9600);
}

void loop() {
    int buttonState = digitalRead(8);
    Serial.println(buttonState);
    delay(200);
}

digitalRead() returns either HIGH (1) or LOW (0), depending on the voltage currently present on that pin. Lesson 3.5 puts this into practice with a real physical button.

Serial Monitor: Serial.begin(9600) and Serial.println(), used above, let your Arduino send text back to your computer, viewable via Tools > Serial Monitor in the IDE. This is one of the most useful debugging tools you have — printing a sensor's raw value is often the fastest way to understand what's actually happening in a circuit.

5. Reading Your Board's Pin Labels

Every pin's capability is printed directly on the Arduino board itself, next to the pin headers — numbers for digital pins (often with a "~" beside PWM-capable ones), and "A0"–"A5" for analog input pins. Learning to read your specific board, rather than memorising a diagram, is a skill worth building early — different Arduino models have different pin counts and layouts.

Try it yourself:
  1. Look at your physical Arduino board and identify which pins are marked with a "~" (PWM-capable).
  2. Write a program that sets pin 7 HIGH, waits one second, then LOW — without any component connected yet, just to confirm it uploads and runs without errors.
  3. Add Serial.begin(9600) and print a message each time the pin changes state, so you can watch it happen in the Serial Monitor.
  4. Challenge: research what INPUT_PULLUP does as an alternative to INPUT — you'll meet it properly in Lesson 3.5.
