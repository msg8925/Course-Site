Interfacing a Switch

Section focus: Arduino Programming — Lesson 3.5  |  Duration: ~45 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Wire a push button as a digital input
  • Explain what a "floating" pin is and why it causes unreliable readings
  • Use INPUT_PULLUP to solve that problem without an extra resistor
  • Use a button to control an LED, combining input and output in one program
Real-world analogy: A floating input pin is like asking someone a yes/no question over a bad phone line that keeps cutting out — without a clear signal either way, they might guess "yes" one moment and "no" the next, essentially at random. A pull-up resistor is like fixing that connection so there's always a clear, definite answer unless the button is actively pressed to change it.

1. The Problem: A Floating Pin

You might expect a digital input to simply read LOW when a button isn't pressed. In reality, if a pin is left completely disconnected (floating) when the button is open, it can pick up tiny amounts of electrical noise from its surroundings and report HIGH or LOW essentially at random. A button needs to guarantee a definite, known state when it's not pressed, not just when it is.

2. The Solution: Pull-Up or Pull-Down Resistors

A pull-up resistor connects the pin to 5V through a large resistor by default, guaranteeing it reads HIGH when the button isn't pressed, and pulls it LOW only when the button actively connects it to GND. A pull-down resistor does the reverse. Both solve the same floating-pin problem — which one you use often comes down to available components and personal wiring preference.

The easier option: INPUT_PULLUP. Rather than wiring a separate physical pull-up resistor, the Arduino has one built in in that you can enable in software: 
pinMode(8, INPUT_PULLUP);
With this, the pin reads HIGH by default, and LOW when the button is pressed and connects it to GND — the logic is "backwards" from what many people expect at first (pressed = LOW), which is worth remembering when writing your if-statements.

3. Step-by-Step: Button-Controlled LED

1Wire the button

  • One side of the button → Arduino Pin 8
  • The same side of the button → Arduino GND (through the button, when pressed)

With INPUT_PULLUP enabled in code, no external resistor is needed — just the button itself, bridging Pin 8 to GND when pressed.

2Wire the LED

Exactly as in Lesson 3.4: LED's anode → 220Ω resistor → Pin 7; cathode → GND.

3Write the program

const int buttonPin = 8;
const int ledPin = 7;

void setup() {
    pinMode(buttonPin, INPUT_PULLUP);
    pinMode(ledPin, OUTPUT);
}

void loop() {
    int buttonState = digitalRead(buttonPin);

    if (buttonState == LOW) {  // LOW means pressed, with INPUT_PULLUP
        digitalWrite(ledPin, HIGH);
    } else {
        digitalWrite(ledPin, LOW);
    }
}

4Upload and test

Upload the code. The LED should light only while the button is actively held down, and turn off the instant it's released.

Troubleshooting

  • LED is on all the time, button does nothing: double check the if-statement's logic — with INPUT_PULLUP, pressed means LOW, not HIGH.
  • Reading seems random/flickery: confirm INPUT_PULLUP is actually being used, not plain INPUT with nothing else wired.
  • Nothing happens at all: check the button is actually bridging the pin to GND when pressed, using a multimeter's continuity mode if unsure.
Looking ahead: this exact input-reading pattern reappears constantly — a line sensor on your vehicle isn't a simple button, but reading it, checking its state, and reacting with an if-statement follows precisely this same shape. A start/stop button for your finished vehicle (mentioned back in the parts list conversation) would also use exactly this circuit.
Try it yourself:
  1. Reverse the logic so the LED is normally on, and turns off only while the button is held.
  2. Add a second button and LED pair on different pins, independent of the first.
  3. Challenge: make a single button toggle the LED's state (on stays on after release, until pressed again) rather than only lighting while held — this requires storing whether the LED is currently on in a variable, and changing it only on the moment the button is first pressed, not while held.
