Measuring Distance with the HC-SR04 Ultrasonic Sensor

Session focus: Sensors — ultrasonic distance measurement  |  Duration: ~60 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Explain how the HC-SR04 measures distance using sound
  • Wire the sensor to an Arduino correctly
  • Write a program that reads distance and prints it to the Serial Monitor
  • Use a measured distance to trigger a simple decision in code (e.g. "too close")
Real-world analogy: This sensor works exactly like a bat, or like shouting into a canyon and timing the echo. It sends out a short "shout" of ultrasonic sound (too high-pitched for us to hear), then times exactly how long it takes for the echo to bounce back off the nearest object. Since sound travels at a known, constant speed, that time tells us the distance.

2. Understanding the HC-SR04

The two round discs on the front of the module are its "eyes": one is a tiny speaker that sends out an ultrasonic pulse, and the other is a tiny microphone that listens for the echo. The module has four pins:

PinFunctionConnects To
VCCPowerArduino 5V
TrigTrigger — tells the sensor to send a pulseArduino digital pin (e.g. Pin 9)
EchoEcho — goes HIGH for exactly as long as the pulse took to returnArduino digital pin (e.g. Pin 10)
GNDGroundArduino GND
The core idea: The Arduino briefly sets Trig HIGH to fire a pulse, then measures how long Echo stays HIGH waiting for it to bounce back. That time (in microseconds) is converted into a distance using the speed of sound.

Figure 1: Trig sends the ultrasonic pulse; Echo reports how long it took to bounce back.

3. Step-by-Step Instructions

1Wire the sensor

  • VCC → Arduino 5V
  • Trig → Arduino Pin 9
  • Echo → Arduino Pin 10
  • GND → Arduino GND

2Write the program

// HC-SR04 Distance Measurement Example
const int trigPin = 9;
const int echoPin = 10;

void setup() {
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
  Serial.begin(9600);
}

void loop() {
  // Send a short pulse to trigger a measurement
  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  // Measure how long the echo pin stays HIGH (in microseconds)
  long duration = pulseIn(echoPin, HIGH);

  // Convert time into distance (cm)
  // Sound travels ~0.034 cm per microsecond; divide by 2
  // because the pulse travels there AND back
  float distanceCm = (duration * 0.034) / 2;

  Serial.print("Distance: ");
  Serial.print(distanceCm);
  Serial.println(" cm");

  delay(500);
}

3Upload and test

Upload the code, then open the Serial Monitor (Tools → Serial Monitor, or Ctrl+Shift+M) and set it to 9600 baud. Move your hand toward and away from the sensor and watch the distance readings change.

Troubleshooting

  • Readings are 0 or wildly inconsistent: check Trig and Echo aren't swapped, and that GND is connected.
  • Nothing appears in Serial Monitor: check the baud rate is set to 9600 to match Serial.begin(9600).
  • Readings jump around even when nothing moves: this is normal to a small degree — ultrasonic sensors are sensitive to angled or soft surfaces that scatter sound rather than reflecting it cleanly.
  • Very close objects (under ~2cm) don't register: this is a physical limitation of the sensor, not a wiring fault.

4. Making a Decision from the Reading

Sensors become useful once code responds to what they detect. Here's the same program extended to react when something gets close:

float distanceCm = (duration * 0.034) / 2;

if (distanceCm < 10) {
  Serial.println("Object too close!");
} else {
  Serial.println("Clear");
}

5. Why This Matters

This is the sensor input half of the "sense-then-act" pattern that runs through robotics: a sensor measures the world, code makes a decision, and a motor responds. In our line-following vehicle, this same pattern applies — later sessions swap the ultrasonic sensor for a line sensor, but the structure (read sensor → decide → drive motor) stays identical.

Try it yourself:
  1. Change the threshold in the if-statement from 10cm to a distance of your choice, and test it.
  2. Add a second condition so the program prints "Object very close!" under 5cm, "Object close" under 20cm, and "Clear" otherwise.
  3. Challenge: combine this with the DC motor lesson — write a program that drives a motor forward, but stops it automatically if the sensor detects an object within 15cm.
