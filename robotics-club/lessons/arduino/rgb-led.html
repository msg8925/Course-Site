Controlling an RGB LED with Arduino

Session focus: Digital Output — mixing colour with an RGB LED module  |  Duration: ~60 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Explain how three separate LEDs in one package can produce any colour
  • Identify whether your module is common-cathode or common-anode, and why it matters
  • Wire the module to an Arduino using three PWM pins
  • Write code that mixes red, green, and blue to produce custom colours
Real-world analogy: Think of painting with three overlapping torches — one red, one green, one blue — all shone onto the same spot on a wall. Where they overlap, the colours blend: full red and green together makes yellow, all three at full brightness makes white, and dimming one torch shifts the blend. An RGB LED does exactly this in miniature, with three tiny LED chips in a single package.

2. Understanding the Module — Common Cathode vs Common Anode

An RGB LED is really three separate LEDs sharing one package, so it has four pins instead of two: one for each colour, and one shared "common" pin. Which type you have changes how you wire and code it:

TypeCommon pin connects toTo light a colour...
Common cathodeGNDSet that colour's pin HIGH (or a positive PWM value)
Common anode5VSet that colour's pin LOW (or an inverted PWM value)
How to tell which one you have: Most breakout boards like the SMD 5050 module print it on the board, or it's stated on the packaging/listing you bought it from. If unlabelled, you can test it: connect the common pin to GND through a resistor, briefly touch each colour pin to 5V — if the LEDs light up, it's common cathode. If nothing lights up that way, try connecting the common pin to 5V instead and touching each colour pin to GND; if that lights it, it's common anode. This lesson assumes common cathode, the more frequently supplied type — if yours is common anode, the wiring is identical but every analogWrite() value in the code needs to be inverted (subtract it from 255).

3. Step-by-Step Instructions

1Wire the module

  • Red pin → Arduino Pin 9
  • Green pin → Arduino Pin 10
  • Blue pin → Arduino Pin 11
  • Common pin → Arduino GND (common cathode)

All three signal pins must be PWM-capable (marked with a "~" on the board silkscreen) since brightness mixing depends on it.

2Write the program

// RGB LED — Basic Colour Mixing
const int redPin = 9;
const int greenPin = 10;
const int bluePin = 11;

void setup() {
  pinMode(redPin, OUTPUT);
  pinMode(greenPin, OUTPUT);
  pinMode(bluePin, OUTPUT);
}

void setColor(int r, int g, int b) {
  analogWrite(redPin, r);
  analogWrite(greenPin, g);
  analogWrite(bluePin, b);
}

void loop() {
  setColor(255, 0, 0);    // red
  delay(1000);

  setColor(0, 255, 0);    // green
  delay(1000);

  setColor(0, 0, 255);    // blue
  delay(1000);

  setColor(255, 255, 0);  // yellow (red + green)
  delay(1000);

  setColor(255, 255, 255); // white (all three)
  delay(1000);

  setColor(0, 0, 0);       // off
  delay(1000);
}

3Upload and test

Upload the code and watch the module cycle through red, green, blue, yellow, white, and off. If the colours look wrong or nothing lights up, see troubleshooting below before assuming the code is at fault.

If every colour looks inverted (dim when it should be bright, or lit when it should be off): you likely have a common-anode module rather than common-cathode. Either rewire the common pin to 5V and invert every value in code (255 - value), or check your supplier's listing to confirm which type you actually have.

Troubleshooting

  • Only one or two colours ever appear: check each colour pin is on a genuinely PWM-capable pin (marked "~"), not a regular digital pin.
  • Colours look muddy or don't match the code: double check R, G, B pins aren't swapped from what's written in the sketch.
  • Nothing lights up at all: confirm the common pin is wired to GND (or 5V, if common anode) and that connection is solid.
  • Colours are dim compared to expected: some modules include built-in resistors, others don't — if yours doesn't and colours seem unusually bright or hot to the touch, add a 220Ω resistor in series with each colour line.

4. Making Custom Colours

Because each channel accepts any value from 0–255, you're not limited to the six "pure" combinations above — you can mix any colour a screen can display:

// A few custom colours to try
setColor(255, 105, 180);  // pink
setColor(255, 140, 0);    // orange
setColor(75, 0, 130);     // indigo

Any online "RGB colour picker" will give you R, G, B numbers for a colour you have in mind — try picking a colour, finding its RGB values, and reproducing it on the module.

5. Why This Matters

This is the same additive colour-mixing principle used in every screen you look at — TVs, phone displays, and computer monitors are all just grids of tiny red, green, and blue lights at different brightnesses. In robotics, RGB LEDs are commonly used as status indicators — for example, a vehicle that glows green when working correctly, amber when something needs attention, and red when it detects a fault or obstacle.

Try it yourself:
  1. Write a smooth fade from red to green to blue and back, changing one value at a time instead of jumping between fixed colours.
  2. Look up the RGB values for your favourite colour and reproduce it on the module.
  3. Challenge: combine this with the HC-SR04 lesson — turn the LED green when an object is far away, amber when it's medium distance, and red when it's very close.
