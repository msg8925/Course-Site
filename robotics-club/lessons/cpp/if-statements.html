If Statements and Conditions

Section focus: C/C++ Fundamentals — Lesson 1.3  |  Duration: ~45 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Explain why programs need to make decisions, not just run straight through
  • Write comparisons using C++'s comparison operators
  • Use if, else if, and else to control which code runs
  • Combine multiple conditions using && and ||
Real-world analogy: This is exactly the logic you already use crossing a road: if the light is green, walk; otherwise, wait. You don't need every possible instruction pre-planned — you just need a rule, and you apply it to whatever situation you're actually in. An if-statement is how a program applies a rule instead of blindly running the same fixed steps every time, regardless of the situation.

1. Why Programs Need Decisions

Every program you wrote in the last two lessons ran the exact same instructions every single time, regardless of anything. Real programs need to react differently depending on circumstances — a game needs to know if you've won, a thermostat needs to know if a room is too cold, and (soon) your Arduino will need to know if a sensor detected something. The if statement is how C++ expresses "do this, but only when a certain condition is true."

2. Your First If Statement

#include <iostream>

int main() {
    int age = 13;

    if (age >= 13) {
        std::cout << "You're a teenager!" << std::endl;
    }

    return 0;
}

The condition inside the parentheses — age >= 13 — is evaluated as either true or false. If it's true, the code inside the curly braces runs. If it's false, that whole block is skipped entirely, as if it wasn't there.

The most common beginner mistake in all of C++: writing if (age = 13) with a single = instead of if (age == 13) with two. A single = doesn't compare — it assigns, overwriting age with the value 13 and (confusingly) often still "succeeding." Always double-check you've used == when comparing values inside a condition.

4. Else and Else If

Real decisions usually have more than one possible outcome:

#include <iostream>

int main() {
    int score = 72;

    if (score >= 90) {
        std::cout << "Grade: A" << std::endl;
    } else if (score >= 80) {
        std::cout << "Grade: B" << std::endl;
    } else if (score >= 70) {
        std::cout << "Grade: C" << std::endl;
    } else {
        std::cout << "Grade: D or below" << std::endl;
    }

    return 0;
}

C++ checks each condition from top to bottom and runs the first block whose condition is true, then skips all the rest — even if a later condition would also have been true. else (with no condition of its own) catches anything that didn't match any of the above.

5. Combining Conditions

Sometimes a decision depends on more than one thing at once:

OperatorMeaningExample
&&AND — both sides must be trueage >= 13 && age <= 19
||OR — at least one side must be trueage == 12 || age == 13
!NOT — flips true to false, or false to true!isRaining
int age = 13;

if (age >= 13 && age <= 19) {
    std::cout << "You're a teenager!" << std::endl;
}
Looking ahead: once your Arduino is reading real sensors, this exact pattern is how you'll make decisions like "if the distance reading is less than 10cm, stop the motor" or "if both line sensors see a light surface, drive straight." The syntax you're practising now with plain numbers is identical to what you'll use with sensor readings later.
Try it yourself:
  1. Write a program that stores a temperature in an int variable and prints "Hot", "Warm", or "Cold" depending on its value, using if/else if/else.
  2. Write a condition using && that checks whether a number is between 1 and 100 (inclusive).
  3. Deliberately write if (score = 100) with a single equals sign, run it, and see what happens. Does the program behave the way you'd expect, or does it reveal the bug from section 3?
  4. Challenge: write a simple password checker — store a password in a std::string, ask nothing (just hardcode a guess), and print "Access granted" or "Access denied" by comparing the guess to the real password with ==.
