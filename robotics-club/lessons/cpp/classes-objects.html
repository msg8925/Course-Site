Classes and Objects

Section focus: C/C++ Fundamentals — Lesson 1.7  |  Duration: ~45 minutes

Learning Objectives

By the end of this session, you will be able to:

  • Explain the difference between a class and an object
  • Write a simple class with member variables and member functions
  • Create multiple objects from the same class, each with its own independent data
  • Recognise this same pattern already in use, in a library you'll soon meet on the Arduino
Real-world analogy: A class is like a blueprint for a house — it describes what every house of that design will have (bedrooms, doors, a kitchen) without being an actual house itself. An object is an actual house built from that blueprint. You can build many houses from one blueprint, and each one is separate — painting one house blue doesn't affect the others, even though they all started from the same plan.

1. Why Bundle Data and Functions Together?

So far, your variables and functions have lived separately — a function like square(int number) takes in data, but doesn't "belong" to any particular piece of data. Sometimes it makes more sense to bundle related data and the functions that act on it into a single unit. Think of a robot's motor: it has data (its current speed, its direction) and behaviours (turn on, turn off, change speed) that all clearly belong together. A class is how C++ expresses that bundling.

2. Defining a Class

#include <iostream>

class Motor {
public:
    int speed;

    void turnOn() {
        speed = 100;
        std::cout << "Motor running at speed " << speed << std::endl;
    }

    void turnOff() {
        speed = 0;
        std::cout << "Motor stopped" << std::endl;
    }
};

int main() {
    Motor leftMotor;
    leftMotor.turnOn();
    leftMotor.turnOff();
    return 0;
}

Here, Motor is the class (the blueprint), and leftMotor is an object (an actual instance built from it). speed is a member variable — data that belongs to each Motor object. turnOn() and turnOff() are member functions — behaviours each Motor object can perform. Notice the dot (leftMotor.turnOn()) — this is how you tell C++ "call this function, on this specific object."

What does public: mean? It marks everything below it as accessible from outside the class — i.e. from your main() function. There's a more restrictive alternative (private:) used in larger programs to hide internal details, but for these early lessons, public: is all you need.

3. Multiple Objects, Independent Data

This is the real payoff of classes — you can create as many objects as you like from one class, and each keeps its own separate data:

#include <iostream>

class Motor {
public:
    int speed;

    void turnOn() {
        speed = 100;
    }

    void turnOff() {
        speed = 0;
    }
};

int main() {
    Motor leftMotor;
    Motor rightMotor;

    leftMotor.turnOn();
    // rightMotor hasn't been turned on yet

    std::cout << "Left speed: " << leftMotor.speed << std::endl;
    std::cout << "Right speed: " << rightMotor.speed << std::endl;

    return 0;
}

This prints Left speed: 100 and Right speed: 0 — turning on leftMotor had no effect on rightMotor, even though they were built from the exact same blueprint. This is exactly the situation your line-following vehicle will be in: two motors, one class, two independent objects.

4. Adding Parameters to Member Functions

Member functions can take parameters, just like the standalone functions from the last lesson:

class Motor {
public:
    int speed;

    void setSpeed(int newSpeed) {
        speed = newSpeed;
        std::cout << "Speed set to " << speed << std::endl;
    }
};

int main() {
    Motor leftMotor;
    leftMotor.setSpeed(75);
    return 0;
}
Looking ahead: you're about to meet this exact pattern on the Arduino itself. The Servo library from the servo motor lesson, and the Stepper library from the stepper motor lesson, are both classes — that's why their code looks like myServo.attach(9); or myServo.write(90);. You were already using objects and member functions in those lessons; now you know the name for what was happening, and you have the tools to write your own.
Try it yourself:
  1. Add a member function reverse() to the Motor class that sets speed to a negative version of its current value (hint: speed = -speed;).
  2. Create a class called Light with a member variable bool isOn and member functions turnOn() and turnOff() that set it appropriately.
  3. Create three separate Motor objects, set each to a different speed using setSpeed(), and print all three speeds to confirm they're independent.
  4. Challenge: add a member function printStatus() to your Motor class that prints whether the motor is currently stopped, running forward, or running in reverse, based on the sign of speed (using if-statements from Lesson 1.3).
