Basic Movement Functions

Section focus: Robotic Vehicle — Drive & Motor Subsystem — Lesson 4.2.2  |  Duration: ~40 minutes

Builds on: Lesson 4.2.1's wiring, and 1.6 Functions. This lesson doesn't introduce new hardware — it reorganises the code you already have into a form that's actually usable in the rest of the build.

Learning Objectives

By the end of this session, you will be able to:

  • Explain why repeating raw motor-pin code everywhere becomes unmanageable
  • Write named functions — forward(), stop(), turnLeft(), turnRight() — that wrap the low-level pin control
  • Call these functions to build a short sequence of movements

1. The Problem With Lesson 4.2.1's Code

Directly writing digitalWrite() and analogWrite() calls every time you want the vehicle to move is exactly the kind of repetition Lesson 1.6 warned about. Worse, once your line-following logic (Lesson 4.3.1) needs to make dozens of small steering decisions per second, reading a wall of raw pin-control code will make that logic far harder to follow than it needs to be.

2. Wrapping Motor Control in Functions

const int leftIN1 = 8, leftIN2 = 9, leftENA = 10;
const int rightIN3 = 11, rightIN4 = 12, rightENB = 13;

void setup() {
    pinMode(leftIN1, OUTPUT);
    pinMode(leftIN2, OUTPUT);
    pinMode(leftENA, OUTPUT);
    pinMode(rightIN3, OUTPUT);
    pinMode(rightIN4, OUTPUT);
    pinMode(rightENB, OUTPUT);
}

void forward(int speed) {
    digitalWrite(leftIN1, HIGH);
    digitalWrite(leftIN2, LOW);
    analogWrite(leftENA, speed);

    digitalWrite(rightIN3, HIGH);
    digitalWrite(rightIN4, LOW);
    analogWrite(rightENB, speed);
}

void stopMotors() {
    analogWrite(leftENA, 0);
    analogWrite(rightENB, 0);
}

void turnLeft(int speed) {
    analogWrite(leftENA, 0);       // left wheel stops
    digitalWrite(rightIN3, HIGH);
    digitalWrite(rightIN4, LOW);
    analogWrite(rightENB, speed);  // right wheel drives
}

void turnRight(int speed) {
    digitalWrite(leftIN1, HIGH);
    digitalWrite(leftIN2, LOW);
    analogWrite(leftENA, speed);   // left wheel drives
    analogWrite(rightENB, 0);      // right wheel stops
}

void loop() {
    forward(200);
    delay(1000);
    turnLeft(200);
    delay(500);
    forward(200);
    delay(1000);
    stopMotors();
    delay(2000);
}
Why stopMotors() and not stop()? stop happens to already be used elsewhere in some Arduino libraries, so giving your function a slightly more specific name avoids a naming clash. This is a small but genuinely useful habit — descriptive, specific function names cause fewer surprises as a program grows.

3. Why This Matters Going Forward

Compare reading forward(200); turnLeft(200); against reading the raw pin-toggling code from Lesson 4.2.1 — the function-based version reads almost like plain English, describing what the vehicle should do without burying that intent in how it's electrically achieved. This is exactly the payoff Lesson 1.6 promised, and it's about to matter a great deal: Lesson 4.3.1's line-following logic will call these exact functions based on sensor readings, and would be far harder to write and debug directly against raw pins.

Try it yourself:
  1. Get all four functions (forward, stopMotors, turnLeft, turnRight) working and confirm each produces the expected physical movement.
  2. Write a short "dance" sequence in loop() using only these functions — forward, turn, forward, stop, repeat.
  3. Add a reverse(int speed) function, following the same pattern as forward() but with both motors' direction pins swapped.
  4. Challenge: add a spinLeft(int speed) function that rotates the vehicle on the spot (left wheel reverse, right wheel forward), distinct from the curving turnLeft() which only stops one wheel.
