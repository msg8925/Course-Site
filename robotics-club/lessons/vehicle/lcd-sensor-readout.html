Live Sensor Readout on an LCD

Section focus: Robotic Vehicle — Line Sensor Subsystem — Lesson 4.1.3  |  Duration: ~35 minutes

Builds on: 3.7 LCD1602 Displays and Lesson 4.1.2's sensor array. This is a small, practical combination lesson, not new theory.

Learning Objectives

By the end of this session, you will be able to:

  • Explain why an on-board display is more convenient than a laptop for field calibration
  • Display multiple live sensor values on a 16×2 LCD at once
  • Update the display fast enough to be useful, without flickering

1. Why Bother With an LCD Here?

The Serial Monitor from Lesson 4.1.2 works perfectly well — but it requires your Arduino to stay tethered to a laptop. Once you're testing on an actual section of tape on the floor, possibly walking the vehicle around by hand, constantly checking a laptop screen is impractical. A small onboard LCD lets you glance directly at the vehicle itself and immediately see what its sensors are detecting, which is exactly what you need during the calibration process in Lesson 4.1.4.

2. Displaying Multiple Values on a 16×2 Screen

A 16×2 LCD has limited space —16 characters per row, 2 rows total. With 5 sensors, that's roughly 3 characters per sensor if you want them all visible in one row, which is tight but workable for small numbers, or you can split them across both rows.

#include <LiquidCrystal.h>

LiquidCrystal lcd(12, 11, 5, 4, 3, 2);  // pins from Lesson 3.7

const int sensorPins[5] = {A0, A1, A2, A3, A4};
int sensorReadings[5];

void setup() {
    lcd.begin(16, 2);
    for (int i = 0; i < 5; i++) {
        pinMode(sensorPins[i], INPUT);
    }
}

void loop() {
    for (int i = 0; i < 5; i++) {
        sensorReadings[i] = analogRead(sensorPins[i]);
    }

    lcd.setCursor(0, 0);
    lcd.print(sensorReadings[0]);
    lcd.print(" ");
    lcd.print(sensorReadings[1]);
    lcd.print(" ");
    lcd.print(sensorReadings[2]);

    lcd.setCursor(0, 1);
    lcd.print(sensorReadings[3]);
    lcd.print(" ");
    lcd.print(sensorReadings[4]);
    lcd.print("    ");  // clears leftover digits, as in Lesson 3.7

    delay(150);
}
Don't update the LCD too fast. Refreshing many times per second can cause visible flicker and doesn't give you time to actually read the numbers. A short delay() (100–200ms) between updates, as shown above, keeps the display both stable and responsive enough to be useful.
A cleaner alternative using a loop: the repeated lcd.print() calls above could themselves be written as a loop over the sensorReadings array, similar to Lesson 4.1.2's Serial printout — a good exercise in recognising the same pattern reappearing in a new context.

3. Using This During Testing

With this running, you can now walk the sensor array over a real piece of tape on the floor, watching the numbers change directly on the vehicle, with no laptop required. This is exactly the setup you'll use in the very next lesson to determine real threshold values from your actual competition surface.

Try it yourself:
  1. Get all 5 sensor readings displaying correctly across both LCD rows.
  2. Rewrite the repeated lcd.print() calls as a for loop over the sensor array.
  3. Slide the array over tape by hand and confirm the LCD updates smoothly, without flickering or lag.
  4. Challenge: instead of showing raw numbers, display just "L" or "D" (light/dark) per sensor, using a threshold guess — you'll refine this properly in the next lesson.
