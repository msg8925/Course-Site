Smoother Steering with Multiple Sensors

Section focus: Robotic Vehicle — Control & Decision Logic — Lesson 4.3.3  |  Duration: ~55 minutes

Builds on: Lesson 4.3.1's bang-bang logic — this lesson directly addresses the weaknesses named at the end of that lesson, using all 5 sensors instead of 2.

Learning Objectives

By the end of this session, you will be able to:

  • Explain what "proportional control" means, and why it reduces zig-zagging
  • Calculate a single "error" value representing how far off-centre the line currently is
  • Convert that error into individually adjusted left/right motor speeds
  • Tune a steering strength constant to balance responsiveness against stability

1. The Core Idea: Proportional Correction

Bang-bang control from Lesson 4.3.1 only knows "on course" or "off course, which side" — it has no sense of how far off course the vehicle is, so it always corrects with the same full-strength turn regardless. Proportional control fixes this by calculating a single number representing both direction and severity of the error, then scaling the correction to match — a small drift gets a gentle nudge, a large drift gets a stronger correction.

2. Assigning Weights to Each Sensor

With 5 sensors, assign each a position weight, with the centre sensor at 0 and outer sensors increasingly negative (left) or positive (right):

Figure 1: Position weights — negative for left sensors, positive for right, zero at centre.

3. Calculating the Error

const int weights[5] = {-2, -1, 0, 1, 2};

int calculateError() {
    int error = 0;
    for (int i = 0; i < 5; i++) {
        if (isOnLine[i]) {
            error += weights[i];
        }
    }
    return error;
}

If only the centre sensor (S3, weight 0) sees the line, error is 0 — perfectly centred. If S4 (weight +1) also sees it, error becomes +1 — a small rightward drift. If the line has moved further, so that only S5 (weight +2) sees it, error becomes +2 — a larger rightward drift. Negative error values mean the line has drifted left.

4. Turning Error Into Motor Speeds

const int baseSpeed = 180;
const int turnStrength = 40;  // how strongly to react per unit of error — tune this

void loop() {
    for (int i = 0; i < 5; i++) {
        sensorReadings[i] = analogRead(sensorPins[i]);
        isOnLine[i] = sensorReadings[i] > thresholds[i];
    }

    int error = calculateError();

    int leftSpeed  = baseSpeed + (error * turnStrength);
    int rightSpeed = baseSpeed - (error * turnStrength);

    leftSpeed  = constrain(leftSpeed, 0, 255);
    rightSpeed = constrain(rightSpeed, 0, 255);

    driveMotors(leftSpeed, rightSpeed);  // a new function — see below
}

A positive error (line drifted right) increases the left wheel's speed and decreases the right wheel's — exactly the correction needed to steer back right. constrain() is a built-in Arduino function that clamps a value between a minimum and maximum, preventing speeds from going negative or above 255.

A new movement function is needed: Lesson 4.2.2's forward() assumed both wheels move at the same speed, which no longer fits. Add a more general function: 
void driveMotors(int leftSpeed, int rightSpeed) {
    digitalWrite(leftIN1, HIGH);
    digitalWrite(leftIN2, LOW);
    analogWrite(leftENA, leftSpeed);

    digitalWrite(rightIN3, HIGH);
    digitalWrite(rightIN4, LOW);
    analogWrite(rightENB, rightSpeed);
}

Try it yourself:
  1. Get the proportional steering code running and compare its behaviour directly against Lesson 4.3.1's bang-bang version on the same piece of tape.
  2. Systematically try three different turnStrength values and record which gives the smoothest run.
  3. Test on a curve sharper than your bang-bang version could handle — does proportional control cope better?
