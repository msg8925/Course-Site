RGB Status Indicator

Section focus: Robotic Vehicle — Control & Decision Logic — Lesson 4.3.2  |  Duration: ~30 minutes

Builds on: 3.8 Controlling an RGB LED and Lesson 4.3.1's line-following logic. This is a small addition, not a new subsystem.

Learning Objectives

By the end of this session, you will be able to:

  • Explain why a status light is genuinely useful, not just decorative
  • Add an RGB status colour to each branch of your existing line-following logic
  • Use the indicator to diagnose behaviour without needing a laptop nearby

1. Why Bother With a Status Light?

Once your vehicle is untethered and moving around on the floor, you lose the Serial Monitor as a debugging tool — you can't easily see what decision the code is making at any given moment just by watching the wheels. A simple colour code lets you glance at the vehicle and immediately know what it currently "believes" is happening, which is enormously useful both while developing this logic and later during competition troubleshooting.

2. Choosing a Colour Code

SituationColour
Driving straight (on line)Green
Correcting left or rightAmber (mix of red + green)
Both sensors dark — stopped/lostRed

3. Adding It to Your Existing Logic

const int redPin = 6, greenPin = 7, bluePin = 5;  // from Lesson 3.8, adjust to your actual wiring

void setColor(int r, int g, int b) {
    analogWrite(redPin, r);
    analogWrite(greenPin, g);
    analogWrite(bluePin, b);
}

void loop() {
    for (int i = 0; i < 5; i++) {
        sensorReadings[i] = analogRead(sensorPins[i]);
        isOnLine[i] = sensorReadings[i] > thresholds[i];
    }

    bool left  = isOnLine[1];
    bool right = isOnLine[3];

    if (!left && !right) {
        forward(180);
        setColor(0, 255, 0);        // green: on line
    } else if (left && !right) {
        turnLeft(180);
        setColor(255, 165, 0);      // amber: correcting
    } else if (!left && right) {
        turnRight(180);
        setColor(255, 165, 0);      // amber: correcting
    } else {
        stopMotors();
        setColor(255, 0, 0);        // red: lost / stopped
    }
}
Notice the pattern: every branch of the if-statement now does two things — call a movement function, and set a status colour. This is a common and useful habit: whenever your code makes a decision, consider whether reporting that decision visually would help you (or a judge, during competition) understand what the vehicle is doing.

4. Using This While Debugging

With this running, you can now watch the LED as the vehicle moves along the tape and see, in real time, whether its decisions match what you'd expect given the line's actual shape — flickering rapidly between green and amber on a straight section, for example, might indicate overly sensitive thresholds from Lesson 4.1.4 worth revisiting.

Try it yourself:
  1. Get the three-colour status system working alongside your existing line-following logic.
  2. Watch the LED while the vehicle runs a straight section, then a curved section — does the colour pattern match what you'd predict?
  3. Add a distinct colour (e.g. blue) for a brief moment when the vehicle first powers on, before any sensor readings have been taken, to confirm startup.
  4. Challenge: make the amber colour's exact shade reflect how sharply the vehicle is correcting, using more sensor detail than just two booleans — this previews the idea behind Lesson 4.3.3.
