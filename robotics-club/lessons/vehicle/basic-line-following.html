Basic Line-Following Logic

Section focus: Robotic Vehicle — Control & Decision Logic — Lesson 4.3.1  |  Duration: ~50 minutes

Builds on: 4.1.4 Sensor Calibration (the isOnLine[] array) and 4.2.2 Basic Movement Functions. This lesson is where those two previously separate subsystems finally connect — nothing new to wire.

Learning Objectives

By the end of this session, you will be able to:

  • Explain "bang-bang" control: reacting to a sensor state with a fixed, fully-committed response
  • Write decision logic that reads sensor state and calls the correct movement function
  • Get the vehicle successfully following a straight and gently curved line
  • Identify the specific weaknesses of this simple approach, motivating Lesson 4.3.3

1. The Simplest Possible Strategy: Two Sensors, Bang-Bang Control

Using just two sensors (left and right, straddling the tape), the entire steering decision can be reduced to a small number of cases:

Left sensorRight sensorMeaningAction
LightLightBoth sensors are over the floor — line is centred between themDrive straight
DarkLightLine has drifted under the left sensorTurn left to correct
LightDarkLine has drifted under the right sensorTurn right to correct
DarkDarkBoth sensors see dark — likely an intersection, or the line is lostStop (handle separately for now)

This is called bang-bang control because each decision is all-or-nothing — there's no "turn a little bit," only "turn" or "don't."

2. Writing the Decision Logic

// Assumes isOnLine[] and sensorPins[] from Lesson 4.1.4,
// and forward(), stopMotors(), turnLeft(), turnRight() from Lesson 4.2.2

void loop() {
    for (int i = 0; i < 5; i++) {
        sensorReadings[i] = analogRead(sensorPins[i]);
        isOnLine[i] = sensorReadings[i] > thresholds[i];
    }

    bool left  = isOnLine[1];  // using sensors S2 and S4 as "left" and "right" for a 5-sensor array
    bool right = isOnLine[3];

    if (!left && !right) {
        forward(180);
    } else if (left && !right) {
        turnLeft(180);
    } else if (!left && right) {
        turnRight(180);
    } else {
        stopMotors();  // both dark — revisit this case later
    }
}
Why use S2 and S4 rather than S1 and S5? With a 5-sensor array, the two sensors just either side of centre typically give a more responsive, less twitchy correction than the outermost pair, which only react once the vehicle has drifted quite far off course. Experiment with which pair of sensors gives you the smoothest test results on your actual chassis.

3. Testing on an Actual Line

Place the vehicle on a straight section of tape, sensors straddling it, and power it on. It should creep forward, correcting left or right as it drifts, in a visibly "zig-zagging" fashion rather than perfectly smoothly — this is entirely expected for bang-bang control and not a bug.

Troubleshooting

  • Vehicle immediately spins in place and never goes anywhere: check your turnLeft()/turnRight() functions from Lesson 4.2.2 aren't accidentally using full reverse — they should only slow/stop one side, not spin.
  • Vehicle overcorrects wildly, swinging far off the line each time: try lowering the turn speed relative to the forward speed.
  • Vehicle loses the line on any curve sharper than very gentle: this is an inherent limitation of two-sensor bang-bang control — Lesson 4.3.3 addresses this directly using more sensors.

4. The Weaknesses Worth Naming

Get this working, but don't stop here expecting perfection — bang-bang control has real, inherent limits:

  • Zig-zag motion instead of a smooth path, since every correction is full-strength regardless of how far off-centre the vehicle actually is
  • Poor performance on sharp curves, since only two sensors are used and there's no sense of "how far" off course the vehicle is, only "which side"
  • No graceful handling of intersections, gaps in the tape, or sharp branches — the "both dark" case is currently just a blunt stop
Try it yourself:
  1. Get the vehicle successfully following a straight line using the code above.
  2. Test it on a gentle curve and observe the zig-zag behaviour directly.
  3. Try a sharper curve and note exactly where and how it fails.
  4. Challenge: extend the logic to use all 5 sensors with more specific cases (e.g. "only the centre sensor is dark" vs "centre and one side are both dark") before moving to Lesson 4.3.3's more systematic approach.
