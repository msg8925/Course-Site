01

The Domain Name System (DNS)

You already know that every device reachable on a network needs an IP address. But nobody types 151.101.1.69 into a browser — they type a name, like bbc.co.uk. The Domain Name System (DNS) is the service that translates a human-readable domain name into the IP address a computer actually needs to connect to.

  1. You type a domain name into your browser.
  2. Your device sends that domain name to a DNS server, asking for its IP address.
  3. The DNS server looks up the domain name and replies with the matching IP address.
  4. Your device uses that IP address to actually connect to the website.
Why not just remember IP addresses? Domain names are easier for people to remember, type correctly, and share — and a domain name can keep working even if the website's underlying IP address changes, as long as its DNS record is updated to match.

03

Packet switching: the idea

Once a connection is established, the actual data — a web page, an email, a file — is not sent as one continuous stream. Instead, it's broken into small chunks called packets, each sent across the network separately, and reassembled into the original data once every packet has arrived at its destination.

Crucially, different packets belonging to the very same message can travel via different routes through the network's routers, depending on which paths are free at that moment — and they don't necessarily arrive in the order they were sent.

04

What's in a packet

Every packet carries a small header alongside its share of the actual data, so that the network — and the receiving device — knows what to do with it:

Header fieldPurpose
Destination addressTells each router along the way where the packet ultimately needs to go
Sequence numberRecords this packet's position in the original message, so it can be put back in the right order

Routers along the way read only the destination address on each packet — they don't need to know anything about the message as a whole, just where this one packet needs to go next.

05

Out-of-order arrival and reassembly

Because packets can take different routes, they can easily arrive at their destination in a different order than they were sent — one might take a short, quick path while another gets delayed on a longer one. This is exactly what the sequence number is for: the receiving device holds each arriving packet until it has them all, then uses the sequence numbers to reconstruct the original message in the correct order.

06

Why use packet switching?

  • Efficient sharing: many different devices' packets can travel across the same network links at the same time, interleaved with each other, rather than one connection monopolising a route for its entire duration.
  • Resilience: if a particular route becomes congested or fails partway through, later packets can simply be sent via a different route — the whole transfer doesn't have to restart or fail completely.
What this topic does not cover This course does not require named protocol-stack detail (things like the specific roles of TCP vs IP, or protocols such as HTTP/HTTPS/FTP) or a comparison against alternative switching methods. Keep your answers focused on IP addressing, DNS, URL structure, and the packet-switching mechanics covered above.
