01

Why networks need addressing

A network is only useful if data sent by one device reliably reaches a specific other device, out of potentially millions connected across the world. That requires every device to have an address — and, as this lesson covers, a real network actually relies on two different kinds of address working together, handled by different pieces of hardware.

02

The Network Interface Card (NIC)

A Network Interface Card (NIC) is the hardware that physically connects a device to a network — built into modern motherboards, though once a separate expansion card. Every NIC is given a unique MAC address by its manufacturer, permanently built into the hardware itself.

Wired vs wireless A wired NIC connects via an Ethernet cable; a wireless NIC (WNIC) connects via radio signals to a wireless access point. Either way, the NIC's job is the same: handle the physical sending and receiving of data, and identify the device on the local network.
03

MAC addresses

A MAC (Media Access Control) address is a 48-bit number, permanently assigned to a NIC by its manufacturer, and written as 12 hexadecimal digits in 6 pairs, e.g. 3C:A8:2A:1B:6F:09. It never changes for the life of that hardware, and no two NICs ever share one.

The address is split into two halves: the first half identifies the manufacturer (the Organisationally Unique Identifier, or OUI), and the second half is a unique serial number assigned by that manufacturer.

04

IP addresses

An IP (Internet Protocol) address identifies a device's location on a network, rather than the physical hardware itself. An IPv4 address is a 32-bit number, written as 4 numbers from 0–255 separated by dots (dotted decimal), e.g. 192.168.1.10.

Assigned, not built-in Unlike a MAC address, an IP address is assigned — usually automatically by a router when a device joins a network — and can change: a laptop gets a different IP address on the office network than at home, even though its MAC address never changes.

05

MAC vs IP: two jobs, not one

It's tempting to think one address should be enough — so why do networks bother with both? Because they solve two different problems:

  • MAC addresses identify a specific piece of hardware within a local network (a LAN) — used to get a frame of data to the correct device once it's already on the right local network.
  • IP addresses identify which network — and which device on it — data needs to reach, potentially across many networks joined together (like the internet) — used to work out which direction to send data in the first place.

Section 08 traces an actual journey using both together, but first, the two pieces of hardware that do the forwarding.

06

Switches

A switch connects multiple devices together within a single local network, and uses MAC addresses to decide where to send each frame of data — learning which MAC address is reachable down which physical cable, and forwarding data only to the correct one, rather than broadcasting it to every device.

07

Routers

A router connects separate networks together — most commonly, a home or office LAN to the wider internet — and uses IP addresses to decide where to forward data between them. When a device wants to reach an address outside its own local network, it sends the data to its router (its "default gateway"), which works out the next step of the journey.

The key takeaway The IP address decided the overall direction — that B is on a different network, reached via the router. The MAC address handled the local delivery at each end — getting the frame from A to the router's LAN1 side, and from the router's LAN2 side to B. Neither address could do the other's job alone.
