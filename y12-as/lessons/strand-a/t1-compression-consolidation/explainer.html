01

Quick recap

Three ideas from last week, in one place before we push further with them:

Lossy vs lossless
Lossless can be perfectly reversed; lossy permanently discards some data for a smaller file.
RLE
Replaces runs of repeated values with a count and a value. Lossless.
Compression ratio
Original size ÷ compressed size.

02

RLE on a real image

So far you've RLE-encoded single strings. A real exam question is just as likely to show you a small 2D image — a grid of black and white pixels — and ask you to RLE-encode it row by row, treating each row as its own string of repeated values.

The method doesn't change

Encode each row exactly as you did before — count then value, for each run — and just do it once per row. The only new skill is reading the runs off a 2D grid instead of a 1D string.

04

Combining file size and compression

A common exam pattern chains two calculations together: first work out an image's uncompressed size from its resolution and colour depth (from Image Representation), then apply a given compression ratio to find its final, compressed size.

The two-step method

Step 1: uncompressed size = width × height × colour depth (in bits, then convert to bytes). Step 2: compressed size = uncompressed size ÷ compression ratio. Do them in order, and don't skip writing down the uncompressed size — exam mark schemes usually award marks for that intermediate step.

06

Exam-style tips

  • Show your intermediate values. Multi-step questions usually give marks for each correct step, even if your final answer goes wrong.
  • State units at every step (bits vs bytes), and convert deliberately — don't let a bits/bytes mix-up creep in silently.
  • Read the image before assuming RLE will help. If a question shows a genuinely complex or noisy grid, be ready to say RLE performs poorly (or worse than the original) — that's a valid, testable exam answer.
  • Justify lossy vs lossless with the scenario, not a general rule — "this is a company logo that must remain pixel-perfect" points to lossless; "this is a holiday photo shared online" points to lossy.

07

Key takeaways

  • RLE on a 2D image is applied row by row, using exactly the same count-then-value method as a 1D string.
  • A simple, blocky image compresses well with RLE; a complex or alternating one can end up larger than the original.
  • Multi-step exam questions often chain file size and compression ratio together — calculate the uncompressed size first, then apply the ratio.
  • Always justify a lossy/lossless choice against the specific scenario given, not a general preference.
