Binary Coded Decimal (BCD)

A different way to store denary numbers in binary — one digit at a time — that trades storage efficiency for something digital displays care about far more.

01

Why this matters

You already know how to convert a whole denary number into pure binary. Binary Coded Decimal (BCD) does something different: instead of converting the whole number at once, it converts each digit separately, and stores the digits' binary codes side by side.

This seems like an odd extra step — and it does cost you some efficiency — but it solves a very specific, very common problem: displaying digits.

02

How BCD works

Each denary digit (0–9) is converted to its own 4-bit binary code — a nibble — and the nibbles are simply placed next to each other, digit by digit.

Worked example — encoding 172

1 → 0001
7 → 0111
2 → 0010

Concatenated: 0001 0111 0010. Notice this is not the same as converting 172 straight to pure binary (which would be 10101100) — BCD keeps each digit's identity intact inside its own nibble.

04

Invalid BCD patterns

A nibble has 16 possible patterns (0000 to 1111), but denary digits only go up to 9. That leaves six patterns — 1010, 1011, 1100, 1101, 1110, 1111 (10–15) — that never appear in valid BCD. If you ever see one of these in a BCD-encoded value, something has gone wrong.

Cost of this restriction

Those six unused patterns per nibble are exactly why BCD is less space-efficient than pure binary — it never uses more than 10 of the 16 values a nibble could represent.

06

Practical applications

BCD earns its keep whenever a system needs to work with individual digits rather than a number as a whole — most obviously, anything with a digit-by-digit display:

  • Digital clocks and calculators: each digit position drives its own display segment; BCD means no conversion is needed to know what to light up.
  • Digital weighing scales and multimeters: readings are naturally digit-by-digit, so BCD avoids the extra step of converting pure binary back into separate digits just to display them.
The trade-off in one sentence

Pure binary is more compact; BCD is easier to convert back into individual digits for display. Choose based on which one your system actually needs.

07

Key takeaways

  • BCD encodes each denary digit as its own 4-bit nibble, then concatenates the nibbles — it does not convert the whole number to pure binary.
  • Only 10 of a nibble's 16 possible patterns (0000–1001) are valid in BCD; 1010–1111 never appear.
  • BCD generally needs more bits than pure binary for the same number, because those six patterns per nibble go unused.
  • BCD is chosen when individual digits need to be processed or displayed directly, such as in digital clocks, calculators, and other digit-based displays.
