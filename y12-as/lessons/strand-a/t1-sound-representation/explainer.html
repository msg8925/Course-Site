Sound Representation

Sound is a smooth, continuous wave — computers only store discrete numbers. Here's exactly how one becomes the other, and what it costs in storage.

01

Why this matters

A sound wave — whether it's a voice, a guitar string, or a car horn — is a continuous, smoothly varying signal. It never "jumps" between values; it flows. A computer, however, can only store a finite list of discrete numbers. Turning one into the other is the job of an ADC: an Analogue-to-Digital Converter.

Two decisions made during that conversion — how often you measure the wave, and how precisely you record each measurement — determine both how accurate the digital copy sounds, and how much storage it takes up.

02

Sampling

Sampling means measuring the amplitude (height) of the analogue wave at regular, fixed time intervals. How often this happens is the sample rate, measured in Hertz (Hz) — samples per second.

A higher sample rate takes more measurements per second, capturing more detail about how the wave changes — particularly important for accurately reproducing higher-pitched sounds.

Why 44,100 Hz?

CD-quality audio famously uses a sample rate of 44,100 Hz. This isn't arbitrary: human hearing tops out at roughly 20,000 Hz, and a sample rate needs to be a little over twice the highest frequency you want to capture accurately. This is extra context, not something you need to derive yourself — just useful for understanding where the number comes from.

03

Quantization

Each sample also needs to be stored as a binary number, which only has a limited number of possible values. Quantization means rounding each measured amplitude to the nearest value that can actually be represented, given the number of bits available — the resolution or bit depth.

An 8-bit resolution allows 28 = 256 distinct amplitude levels; 16-bit allows 216 = 65,536 levels. More levels mean each sample can be rounded more precisely, reducing quantization error — the small gap between the true amplitude and the nearest storable level.

The ADC process, step by step

1
Sound arrives as a continuous analogue electrical signal (e.g. from a microphone).
2
The signal's amplitude is sampled — measured at regular intervals, determined by the sample rate.
3
Each sample is quantized — rounded to the nearest level the chosen bit depth can represent.
4
Each quantized level is encoded as a binary number and stored.
5
The result is a sequence of binary numbers that approximates the original wave.

05

Calculating file size

Once you know the sample rate, bit depth, duration, and number of channels, the uncompressed file size follows directly:

The formula

file size (bits) = sample rate × bit depth × duration (seconds) × channels

Worked example — 10 seconds, mono, 8,000 Hz, 8-bit

file size = 8,000 × 8 × 10 × 1 = 640,000 bits = 80,000 bytes

We're expressing this in bytes rather than "KB" on purpose — as you saw a couple of lessons ago, that label gets ambiguous fast. 80,000 bytes is unambiguous.

Worked example — same recording, but stereo

file size = 8,000 × 8 × 10 × 2 = 1,280,000 bits = 160,000 bytes

Stereo simply doubles everything — it's really two mono channels recorded and stored side by side.

07

The trade-offs

Both sample rate and bit depth trade accuracy for storage space, independently:

ChangeEffect on file sizeEffect on accuracy
Double the sample rate×2Captures faster changes in the wave more faithfully (better for high-pitched sound)
Double the bit depth×2Reduces quantization error (less "graininess" in amplitude)
Double both×4Both benefits together — at four times the storage cost
Common mistake

Sample rate and bit depth affect different kinds of accuracy — one is about timing detail, the other is about amplitude precision. Don't treat them as interchangeable; a question asking about "high-pitched sound" points to sample rate, while "smoothness of volume" points to bit depth.

08

Key takeaways

  • Sampling measures the analogue wave's amplitude at regular intervals; the sample rate (Hz) is how often this happens.
  • Quantization rounds each sample to the nearest level the bit depth can represent — more bits means more levels and less error.
  • File size (bits) = sample rate × bit depth × duration × channels.
  • Doubling sample rate or bit depth doubles file size; doubling both quadruples it.
  • Sample rate mainly affects how well fast (high-pitched) changes are captured; bit depth mainly affects how precisely amplitude (volume) is recorded.
