Data Compression: Lossy, Lossless & RLE

Every compressed file makes the same fundamental choice: keep every single bit, or throw some away for a much smaller file. Here's how that choice works, and one concrete technique for making the lossless case happen.

01

Why this matters

Uncompressed files are often far bigger than they need to be — a single uncompressed photo can run to tens of megabytes. Compression shrinks files for storage and transmission, but it always involves a choice: preserve the file exactly, or accept some loss of detail for a much bigger size reduction.

02

Lossy vs lossless

Lossless
The original file can be perfectly reconstructed from the compressed version — no data is discarded. Used where every bit matters: text documents, program files, spreadsheets.
Lossy
Some data is permanently discarded to achieve a much smaller file. The original cannot be exactly recovered — only approximated. Used where the loss is barely noticeable: photos, audio, video.
A useful test

Ask: "if I decompress this, do I get back exactly the original bytes?" If yes, it's lossless. If the result is merely a very close approximation, it's lossy.

03

Compression ratio

The compression ratio measures how effective compression was:

The formula

compression ratio = original size ÷ compressed size

A ratio of 4 means the compressed file is a quarter of the original size. It's sometimes expressed instead as a percentage reduction: (1 − compressed/original) × 100%.

04

Run-Length Encoding

Run-Length Encoding (RLE) is a lossless compression technique. It looks for runs — sequences of the same value repeated consecutively — and replaces each run with just a count and the value, instead of storing the value over and over.

Worked example

Original: AAAAABBBCCCCCCCD (16 characters) Encoded: 5A3B7C1D (8 characters)

Each pair means "repeat this character this many times." 5A means five A's, 3B means three B's, and so on. Decoding just reverses the process: expand each pair back into a run.

07

When RLE works (and when it doesn't)

RLE only helps when there are long runs of repeated values to compress.

Good candidatePoor candidate
Simple black-and-white line art or logos (large blocks of one colour)Photographs (colours vary constantly, few long runs)
Fax scans (mostly white background)Already-compressed files (randomised bit patterns, no repetition left)
RLE can make files bigger

Encoding ABCDE with RLE gives 1A1B1C1D1E — 10 characters instead of 5. With no repeated runs at all, every single character needs its own count-and-value pair, which takes more space than the original. Always check: does this data actually have long runs?

08

Key takeaways

  • Lossless compression can be perfectly reversed; lossy compression permanently discards some data for a smaller file.
  • Compression ratio = original size ÷ compressed size.
  • RLE replaces runs of repeated values with a count and a value — it's lossless, and reversible by expanding each pair back into a run.
  • RLE works well on data with long runs (simple graphics); it can actually increase file size on data with little or no repetition.
  • A high compression ratio doesn't tell you whether a technique is lossy or lossless — those are two separate questions.
