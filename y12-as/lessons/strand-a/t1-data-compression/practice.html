7

Explain why RLE-encoding the string ABCDE actually increases its size rather than reducing it.

Show model answer

There are no repeated characters, so every run has a length of 1. Each character still needs a count-and-value pair, giving 1A1B1C1D1E — 10 characters instead of the original 5. With no runs to exploit, RLE adds overhead instead of saving space.

C

Compression ratio

Use: compression ratio = original size ÷ compressed size.

8

A 12MB file is compressed to 3MB. Calculate the compression ratio.

Show full working
12 ÷ 3 = 4

Answer: 4 (often written 4x or 4:1).

9

A 500KB image is compressed using lossy JPEG to 50KB. Calculate the percentage reduction in file size.

Show full working
(1 \u2212 50/500) \u00d7 100 = (1 \u2212 0.1) \u00d7 100 = 90

Answer: 90% reduction.

D

Good or poor fit?

Decide whether RLE would compress each type of data well.

11

A simple black-and-white logo image made up of large blocks of solid colour. Is this a good or poor candidate for RLE compression? Justify your answer.

Show model answer

Good candidate. Large blocks of solid colour mean long runs of the same pixel value in a row, which is exactly what RLE compresses efficiently — each long run becomes a single count-and-value pair.

12

A photograph with lots of colour variation and fine detail. Is this a good or poor candidate for RLE compression? Justify your answer.

Show model answer

Poor candidate. Colours change frequently from pixel to pixel, so there are few (if any) long runs of repeated values to exploit — RLE may achieve very little compression, or even increase the file size.

Exam-style question

A longer, multi-part question.

13

A simple monochrome image is stored as a string of pixel values: WWWWWWWWBBBBWWWWWWWWWWWWBBWWWW (30 characters, where W = white and B = black).

(a) RLE-encode this string.
(b) Calculate the compression ratio achieved.
(c) State whether RLE is lossy or lossless, and explain how you know.

Show model answer

(a) Breaking into runs: 8 W's, 4 B's, 12 W's, 2 B's, 4 W's:

8W4B12W2B4W

That's 11 characters, encoded from the original 30.

(b)

30 \u00f7 11 \u2248 2.73

(c) RLE is lossless. Decoding 8W4B12W2B4W by expanding each pair back into its run reproduces the original 30-character string exactly, with no loss of information.
