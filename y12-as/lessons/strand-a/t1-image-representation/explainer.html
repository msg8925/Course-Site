Image Representation: Resolution & Colour Depth

Every digital image is just a grid of numbers. How big that grid is, and how many bits describe each square, together decide exactly how many bytes the file takes up.

01

Why this matters

A photo looks nothing like a spreadsheet of numbers — but that's exactly what it is underneath. Two simple settings, decided the moment an image is captured or created, determine exactly how large that spreadsheet needs to be: how many squares it has, and how many bits describe the colour of each one.

02

Pixels and resolution

A bitmap image is a grid of tiny squares called pixels (short for "picture elements"). The resolution is simply the width and height of that grid, in pixels.

Worked example

An image with a resolution of 1920 × 1080 has 1920 × 1080 = 2,073,600 pixels — commonly rounded to "2 megapixels."

03

Colour depth

Each pixel's colour is stored using a fixed number of bits — the colour depth (or bit depth). More bits per pixel means more distinguishable colours are available.

Colour depthColours availableTypical use
1 bit21 = 2Pure black and white
4 bits24 = 16Simple icons, basic graphics
8 bits28 = 256Simple web graphics, GIFs
24 bits224 = 16,777,216"True colour" photographs (8 bits each for red, green, blue)

05

Calculating file size

The formula

file size (bits) = width × height × colour depth

Worked example — a small 4×4 image, 8-bit colour depth

file size = 4 × 4 × 8 = 128 bits = 16 bytes

Worked example — a 1920×1080 photo, 24-bit colour depth

file size = 1920 × 1080 × 24 = 49,766,400 bits = 6,220,800 bytes ≈ 6.22 MB

That's before any compression is applied — real photo files are almost always compressed afterwards, which is exactly what last lesson covered.

Watch the rounding

If the total number of bits doesn't divide evenly by 8, round up to the next whole byte — you can't store half a byte. A 10×10 image at 1-bit depth is 100 bits = 12.5 bytes, which needs 13 bytes of actual storage.

07

The trade-offs

ChangeEffect on file size
Double the colour depth×2
Double both width and height×4
Common mistake

Doubling one dimension (just width, or just height) doubles the file size. Doubling both dimensions together doesn't double it — it quadruples it, because the total number of pixels is width × height, and you've doubled both factors in that multiplication.

08

Key takeaways

  • Resolution is the width × height of an image's pixel grid.
  • Colour depth is the number of bits used per pixel; it determines how many distinct colours (2depth) are available.
  • File size (bits) = width × height × colour depth. Convert to bytes by dividing by 8, rounding up if needed.
  • Doubling colour depth doubles file size; doubling both width and height quadruples it.
  • These calculations give the uncompressed size — real image files are usually compressed afterwards.
