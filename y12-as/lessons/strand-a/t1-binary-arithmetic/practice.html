E

Signed overflow

For each addition, decide whether signed overflow occurs. Answer "yes" or "no".

13

Does signed overflow occur? 01111111 + 00000001

Show full working

Yes. 127 + 1 should be 128, but both operands are positive (sign bit 0) while the result's sign bit is 1 (reading as −128). Same-sign inputs, opposite-sign result — that's the overflow rule.

14

Does signed overflow occur? 10000001 + 11111111

Show full working

No. This one is a trap: there IS a carry out of bit 7 here, which would flag unsigned overflow. But we're interpreting these as signed numbers: −127 + (−1) = −128, and −128 is a perfectly valid signed 8-bit value. Both operands are negative and the result is negative too — same sign in, same sign out, so there's no signed overflow. Carry-out and signed overflow really are independent checks.

Exam-style question

15

A student adds two pairs of 8-bit two's complement numbers:
Pair 1: 01010101 + 00101010
Pair 2: 11010101 + 10101010

For each pair: (a) state the signed decimal value of each operand, (b) compute the 8-bit binary result, and (c) state whether signed overflow occurs, justifying your answer using the overflow rule.

Show model answer

Pair 1: 01010101 = 85, 00101010 = 42 (both positive).

Result: 01111111 = 127. Both operands were positive and the result is positive — same sign preserved, so no overflow. (85 + 42 = 127, which is exactly the largest positive signed value, but still in range.)

Pair 2: 11010101 = −43, 10101010 = −86 (both negative).

Result: 01111111 = +127. Both operands were negative, but the result is positive — sign has flipped, so signed overflow has occurred. This matches expectation: −43 + (−86) = −129, which falls outside the representable range of −128 to +127.
