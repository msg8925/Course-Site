01

Why this matters

Two everyday frustrations turn out to have precise, computer-science explanations. Why does a "500GB" drive show up as roughly 465GB in your file browser? And how does a keyboard press turn into something a processor can actually store and compare?

The first comes down to two different, both-legitimate definitions of "kilo," "mega," and "giga." The second comes down to a single, elegant idea: give every character a number, and store the number.

02

Decimal vs binary prefixes

Computers naturally work in powers of two, but the metric prefixes we borrowed for computing (kilo, mega, giga...) are officially powers of ten. For decades, the computing world used "kilo" loosely to mean 1024 — close enough to 1000, and a convenient power of two. That informal habit is the root of a lot of confusion.

Decimal (SI) prefixValueBinary (IEC) prefixValue
kilo (k)103 = 1,000kibi (Ki)210 = 1,024
mega (M)106 = 1,000,000mebi (Mi)220 = 1,048,576
giga (G)109 = 1,000,000,000gibi (Gi)230 = 1,073,741,824
tera (T)1012tebi (Ti)240

The proper, unambiguous unit names use the binary prefix directly: a kibibyte (KiB) is always exactly 1,024 bytes; a kilobyte (kB), used strictly, is 1,000 bytes.

Where the confusion bites

Storage manufacturers advertise capacity using the decimal definition (1 GB = 1,000,000,000 bytes) — which is technically correct, and makes the number look bigger. Your operating system, however, often calculates free space using binary arithmetic (dividing by 1,073,741,824) while still labelling the result "GB" instead of the correct "GiB". Same bytes, two different-looking numbers.

04

Introducing ASCII

ASCII (American Standard Code for Information Interchange) is a system that assigns every letter, digit, punctuation mark, and common control action a unique number, so that text can be stored and transmitted as binary just like any other data.

Standard ASCII uses 7 bits, giving 128 possible codes (0–127) — though it's almost always stored in a full 8-bit byte, with the extra bit set to 0 (or used for extensions, which we'll meet next lesson).

Worked example

The character 'A' has ASCII code 65. Stored as an 8-bit binary pattern, that's 01000001.

Whenever you press a key, save a text file, or send a message, this is what's actually being stored and moved around underneath.

07

Patterns worth knowing

  • The digit trick: a digit character's ASCII code minus 48 gives its actual numeric value. '7' is code 55; 55 − 48 = 7.
  • The case bit: lowercase letters are always exactly 32 more than their uppercase equivalent. 'a' (97) = 'A' (65) + 32. In binary, this is a single bit: flip bit 5 (the 32s column) and you toggle a letter's case.
Quick check

65 in binary is 01000001. Add 32 (00100000) and you get 01100001 — which is 97, 'a'. The letter itself didn't change conceptually; one bit did.

08

Key takeaways

  • Decimal prefixes (kilo, mega, giga...) are powers of 10; binary prefixes (kibi, mebi, gibi...) are powers of 2. They are not the same size, and the gap grows at larger scales.
  • Storage capacity is usually advertised in decimal units but reported by operating systems using binary arithmetic mislabelled with decimal unit names — that's why your drive "looks smaller."
  • ASCII assigns every character a unique 7-bit (128-value) code, usually stored in a full byte.
  • The ASCII table is organised in blocks: control characters, punctuation, digits, uppercase letters, lowercase letters.
  • Two handy patterns: subtract 48 from a digit character's code to get its value; add or subtract 32 to toggle a letter's case.
