01

The client-server model

A server is a dedicated computer that provides a resource or service to other computers on the network. A client is a computer that requests and uses that resource. In this model, the roles are fixed: a given machine is either a server or a client, not both.

Server typeWhat it provides
File serverCentral storage for shared files
Web serverWeb pages, delivered to browsers on request
Print serverManages a shared printer and its print queue
Email serverSends, receives and stores email

Because the server is dedicated and centralised, the organisation running it can apply security policies, back up data, and roll out updates from one place — every client benefits automatically.

02

The peer-to-peer model

In a peer-to-peer (P2P) network, there is no dedicated server. Every computer — every peer — has equal status, and can act as a client and a server simultaneously: requesting resources from other peers while also providing its own resources to them.

Same hardware, different role assignment The distinction between client-server and peer-to-peer isn't about the physical computers at all — it's about whether the network's design gives one machine a permanently dedicated, centralised role, or treats every machine as equal.
03

Comparing the two models

Client-serverPeer-to-peer
Setup costHigher — needs dedicated server hardware and softwareLower — no dedicated server needed
Central managementEasy — backups, security and updates handled in one placeHard — no single place to enforce policy across every peer
Single point of failureYes — if the server goes down, clients lose the serviceNo — the network keeps functioning if one peer goes offline
Typical useBusiness networks, websites, emailSmall home networks, direct file sharing

05

Thin client vs thick client

This is a separate question from client-server vs peer-to-peer — it's about how much work an individual client machine does for itself, regardless of which network model it's part of.

Thin clientThick client
ProcessingDone mostly by the serverDone mostly by the client itself
Local storage neededLittle to noneSignificant local storage
Hardware cost per machineLower — low-spec hardware is enoughHigher — needs capable local hardware
Works without a network connection?No — depends on the server for almost everythingYes, largely — most of its work doesn't need the server
Security and updatesCentralised and simple — update the server onceMust be managed on every individual machine
Thin clients still need a network A thin client's biggest weakness is exactly its biggest strength elsewhere: because it depends on the server for almost everything, a lost network connection can make it almost unusable, whereas a thick client can often keep working locally.
