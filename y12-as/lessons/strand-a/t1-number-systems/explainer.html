01

Why this matters

You've already met denary and binary. Today we add a third system — hexadecimal — and, more importantly, the reason computer scientists actually use it: it's a compact, human-friendly way of writing binary down.

You've seen hex already without necessarily naming it that way — MAC addresses are written as six pairs of hex digits, and colour codes like #3FA9C8 are hex too. By the end of this page you'll be able to convert fluently between all three systems, including the fast shortcut that skips denary entirely.

02

Three number systems, one idea

Every number system works the same way: each position (column) is worth a power of the base, and you have exactly that many distinct digits to fill each column.

SystemBaseDigits availableColumn values (right to left)
Denary100–9… 1000, 100, 10, 1
Binary20, 1128, 64, 32, 16, 8, 4, 2, 1
Hexadecimal160–9, A–F… 4096, 256, 16, 1

In hexadecimal, the letters A–F stand in for the values 10–15, since a single hex digit needs 16 possible symbols.

03

Denary ↔ binary (recap)

You've done this before, so here's the method as a quick refresher.

Denary to binary: repeated division by 2

Divide by 2 repeatedly, noting the remainder each time. Read the remainders from bottom to top to get the binary answer.

Worked example — convert 156 to 8-bit binary

156 ÷ 2 = 78 remainder 0 78 ÷ 2 = 39 remainder 0 39 ÷ 2 = 19 remainder 1 19 ÷ 2 = 9 remainder 1 9 ÷ 2 = 4 remainder 1 4 ÷ 2 = 2 remainder 0 2 ÷ 2 = 1 remainder 0 1 ÷ 2 = 0 remainder 1

Reading the remainders bottom to top: 10011100. Check: 128 + 16 + 8 + 4 = 156. ✓

Binary to denary: sum the place values

Multiply each bit by its column's place value and add the results together — you did plenty of this in the binary arithmetic lesson.

04

Denary ↔ hex

The same division method works for hex — just divide by 16 instead of 2, and convert any remainder of 10 or more into its letter.

Worked example — convert 200 to hex

200 ÷ 16 = 12 remainder 8 12 ÷ 16 = 0 remainder 12 (C)

Reading bottom to top: C8. Check: (12 × 16) + 8 = 192 + 8 = 200. ✓

Worked example — convert 3F (hex) to denary

3F = (3 × 16) + (F × 1) = (3 × 16) + (15 × 1) = 48 + 15 = 63

Answer: 63.

Worth noticing

Two hex digits can represent 0 to 255 — exactly the range of one byte. That's not a coincidence, and it's the whole reason hex is so useful to programmers.

05

The nibble shortcut

Here's the payoff. Because 16 = 24, every single hex digit corresponds exactly to a group of 4 bits — a nibble. That means you can convert between binary and hex directly, without ever calculating a denary value in between.

Binary00000001001000110100010101100111
Hex01234567
Binary10001001101010111100110111101111
Hex89ABCDEF

Binary to hex: split into nibbles

Split the byte into two groups of 4 bits, then convert each nibble to its hex digit using the table above.

Worked example — convert 10110101 to hex

↓

Answer: B5. Check via denary: 10110101 = 181, and B5 = (11 × 16) + 5 = 181. ✓

Hex to binary: expand each digit back to a nibble

Worked example — convert 2F (hex) to binary

2
↓
0010
F
↓
1111

Answer: 00101111. Check: 47 in denary, and 2F = (2 × 16) + 15 = 47. ✓

Common mistake

Always pad each nibble to exactly 4 bits. Hex digit 5 is 0101, not 101 — a missing leading zero shifts every bit after it.

07

Key takeaways

  • Every number system uses place values based on its base: 10 for denary, 2 for binary, 16 for hex.
  • Hex digits A–F represent the values 10–15.
  • Denary to binary/hex: repeatedly divide by the base, reading remainders from bottom to top.
  • Binary to denary/hex: sum place values, or use the nibble shortcut for hex.
  • The nibble shortcut: because 16 = 24, each hex digit maps directly onto exactly 4 bits — convert nibble by nibble, no denary required.
  • Two hex digits represent one byte (0–255) exactly, which is why hex turns up everywhere bytes do: MAC addresses, colour codes, memory dumps.
