01

Number systems: denary, binary, hexadecimal

Computers store everything in binary, but binary is unwieldy for humans to read, so hexadecimal is used as shorthand — each hex digit represents exactly 4 bits, so an 8-bit byte is always exactly 2 hex digits.

DenaryBinaryHex
0–90000–10010–9
10–151010–1111A–F

To convert binary to hex, split into groups of 4 bits (from the right) and convert each group separately. To convert hex to binary, do the reverse — each hex digit expands to exactly 4 bits.

Worked example Convert 173 (denary) to binary and hex: 173 = 128+32+8+4+1 = 10101101. Split into nibbles: 1010 1101 → A, D → AD in hex.

02

Binary arithmetic: addition, two's complement, overflow

Adding two 8-bit binary numbers works exactly like column addition in denary, carrying into the next column when a column totals 2 or more.

Worked example 77 (01001101) + 54 (00110110) = 131, which is 10000011 in 8 bits.

Two's complement represents negative numbers by inverting every bit of the positive value and adding 1. This makes addition work uniformly whether numbers are positive or negative — the hardware doesn't need separate circuitry for subtraction.

Worked example To represent −54 in 8-bit two's complement: start from 54 (00110110), invert every bit (11001001), then add 1 → 11001010.
Overflow An 8-bit signed (two's complement) number ranges from −128 to +127. Overflow happens when the result of adding two numbers of the same sign produces a result with the opposite sign — a sure sign the true result didn't fit. In the 77 + 54 example above, two positive numbers were added but the result, 10000011, has its leftmost bit set to 1 — which would be read as negative if this byte were being treated as a signed value. That mismatch is the signal that signed overflow has occurred.
03

Binary prefixes

Binary prefixes (kibi, mebi, gibi, tebi) are powers of 1024, and are distinct from the decimal prefixes (kilo, mega, giga, tera) which are powers of 1000. Storage manufacturers often use decimal prefixes; operating systems often report binary ones — which is why a "500 GB" drive shows less than 500 GB once formatted.

PrefixBinary meaningDecimal meaning
kibi / kilo210 = 1024103 = 1000
mebi / mega220 = 1,048,576106 = 1,000,000
gibi / giga230109
tebi / tera2401012
Worked example 5 MiB in bytes = 5 × 1024 × 1024 = 5,242,880 bytes. Compare with 5 MB (decimal) = 5 × 1,000,000 = 5,000,000 bytes — a difference of over 240,000 bytes.

ASCII, Extended ASCII and Unicode

Character setBits per characterCharacters representable
ASCII7128
Extended ASCII8256
Unicode16 or 32 (varies by encoding)over 1 million

Plain ASCII's 128 characters are enough for unaccented English text and control codes, but not for accented letters, symbols, or non-Latin scripts. Extended ASCII doubles the range using the 8th bit. Unicode goes much further, assigning a unique code point to virtually every character in every writing system in use — necessary for genuinely international software.

Worked example The character 'A' has ASCII code 65, which is 01000001 in 7-bit binary (shown here padded to 8 bits).
05

Sound representation

Analogue sound is converted to digital using an Analogue-to-Digital Converter (ADC), which samples the amplitude of the sound wave at regular intervals (the sample rate, in Hz) and stores each sample using a fixed number of bits (the bit depth or resolution).

file size (bits) = sample rate × bit depth × duration (seconds) × channels

Increasing the sample rate captures the waveform more often, improving accuracy of playback but increasing file size. Increasing the bit depth allows finer distinctions in amplitude (more possible volume levels per sample), also improving accuracy at the cost of size.

Worked example A 10-second mono recording at 44,100 Hz, 16-bit: 44,100 × 16 × 10 × 1 = 7,056,000 bits = 882,000 bytes ≈ 861.33 KiB.
06

Image representation

A bitmap image is stored as a grid of pixels, each holding a colour value. The number of bits used per pixel — the colour depth — determines how many distinct colours each pixel can represent (2colour depth possible colours).

file size (bits) = width (pixels) × height (pixels) × colour depth (bits)
Worked example An 800 × 600 image at 24-bit colour: 800 × 600 × 24 = 11,520,000 bits = 1,440,000 bytes ≈ 1406.25 KiB (about 1.37 MiB).

Data compression: lossy vs lossless, and RLE

LosslessLossy
Data on decompressionIdentical to the originalSome detail permanently discarded
Typical useText, program files, anything needing exact recoveryPhotos, audio, video — where minor quality loss is acceptable for much smaller files

Run-Length Encoding (RLE) is a lossless technique that replaces runs of repeated data with a count and the value, which works well on data with long repeated runs (like a simple graphic with blocks of solid colour) and poorly on data with little repetition.

Worked example Encoding AAAABBBCCDAA (12 characters): count each run — 4×A, 3×B, 2×C, 1×D, 2×A — giving 4A3B2C1D2A, just 10 characters. Compression ratio = 12∶10 = 1.2∶1.
08

Binary Coded Decimal (BCD)

BCD encodes a denary number by converting each digit separately into its own 4-bit binary pattern, rather than converting the whole number to pure binary at once. This makes converting back to a human-readable display trivial — each nibble maps straight to one digit — which is why BCD is common in digital clocks, calculators and other seven-segment displays.

Worked example 947 in BCD: 9 → 1001, 4 → 0100, 7 → 0111, giving 1001 0100 0111 (12 bits total — 3 digits × 4 bits each).
BCD is not the same as pure binary 947 in pure binary is 1110110011 (10 bits) — shorter, but not divisible into neat per-digit chunks. BCD trades some space efficiency for much simpler digit-by-digit conversion.
09

Vector graphics

Instead of storing a colour value for every pixel, a vector graphic stores a drawing list of drawing objects (lines, circles, rectangles, curves), each with a set of properties (position, dimensions, colour, line thickness, fill) that describe how to draw it.

BitmapVector
StoresA colour value per pixelA list of objects and their properties
ScalingLoses quality (pixelates)Scales to any size with no quality loss
File size vs complexityDepends on resolution & colour depth, not image complexityDepends on number of objects, not size on screen
Best suited toPhotographs, scanned imagesLogos, diagrams, illustrations with flat colour and clean lines
Worked example A vector circle might be stored as: object = circle, centre = (100, 100), radius = 50, fill colour = red, line thickness = 2. Scaling the whole image up by 10× just means recalculating these numbers — the circle stays perfectly smooth.
