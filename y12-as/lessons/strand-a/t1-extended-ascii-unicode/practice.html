The limits of ASCII

Quick recap before extending into Unicode.

1

Standard (7-bit) ASCII can represent how many different characters in total?

Show full working

7 bits gives 27 = 128 possible codes.

2

Which of these could not be represented in standard 7-bit ASCII?

3

Give one example of a character or symbol that standard ASCII cannot represent, and briefly explain why it's a problem for a global piece of software.

Show model answer

Any character outside the 128 standard ASCII codes is acceptable, for example: an accented letter like é or ñ, a non-Latin script character like 中 or д, a currency symbol like €, or an emoji like 😀.

This matters because software used internationally needs to display names, messages, and content in the user's own language and script — something impossible if only 128 English-oriented codes are available.

B

Extended ASCII & code pages

Using the 8th bit doubles the code space — but creates a new problem.

4

How many different characters can extended (8-bit) ASCII represent in total?

Show full working

8 bits gives 28 = 256 possible codes.

5

Byte 233 (0xE9) means é in the Latin-1 code page. Explain what could go wrong if a piece of software assumes a different code page (e.g. a Cyrillic one) when reading a file that was saved using Latin-1.

Show model answer

The byte value itself (233 / 0xE9) never changes, but each code page assigns it to a different character. If the software assumes the wrong code page, it will display the wrong character entirely — in this case, showing a Cyrillic letter instead of é. Across a whole document, this produces garbled, unreadable text known as mojibake, even though no data has actually been lost or corrupted — it's purely a mismatch in interpretation.

6

What is the general term for text displaying as garbled, incorrect characters because the wrong code page (or encoding) was used to interpret it?

Show full working

Mojibake.

C

Unicode code points

Unicode assigns one unambiguous code point to every character.

7

What is the Unicode code point for 'A'? Give your answer in the form U+XXXX.

Show full working

'A' has the same value in Unicode as in ASCII: 65 in hex is 41, so the code point is U+0041.

8

What is the Unicode code point for é? Give your answer in the form U+XXXX.

Show full working

é is code point U+00E9 (denary 233).

9

True or false: Unicode code point U+00E9 means the same character on every computer system that supports Unicode.

Show full working

True. This is exactly the problem Unicode was designed to solve — one universal, unambiguous meaning per code point, unlike the competing code pages of extended ASCII.

D

UTF-8 byte counts

Use the code point ranges from the explainer to work out how many bytes UTF-8 needs.

10

How many bytes does UTF-8 use to encode the character 'A' (U+0041)?

Show full working

U+0041 is in the range U+0000–U+007F, so UTF-8 uses 1 byte — identical to standard ASCII.

11

How many bytes does UTF-8 use to encode é (U+00E9)?

Show full working

U+00E9 is in the range U+0080–U+07FF, so UTF-8 uses 2 bytes.

12

How many bytes does UTF-8 use to encode € (U+20AC)?

Show full working

U+20AC is in the range U+0800–U+FFFF, so UTF-8 uses 3 bytes.

13

How many bytes does UTF-8 typically use to encode an emoji such as 😀 (U+1F600)?

Show full working

U+1F600 is above U+FFFF, so UTF-8 uses 4 bytes.

14

Explain why any valid ASCII text file is automatically also a valid UTF-8 file.

Show model answer

UTF-8 encodes code points U+0000 to U+007F (the entire standard ASCII range) using exactly 1 byte, with the same bit pattern as standard ASCII itself. Since every byte in an ASCII file is already a valid 1-byte UTF-8 character, the file needs no conversion at all to be read correctly as UTF-8.

E

Exam-style question

A longer, multi-part question bringing the whole lesson together.

15

A company's old customer database was created using the Windows-1253 (Greek) code page. It is being migrated to a new system that uses Unicode (UTF-8) throughout.

(a) Explain one problem that could occur if the old database's raw bytes are copied directly into the new system without first identifying which code page they use.
(b) Explain why converting the data to Unicode, rather than to a different extended-ASCII code page, is a better long-term solution.
(c) The Greek letter iota (ι) has Unicode code point U+03B9. State how many bytes UTF-8 will use to store it, and justify your answer using the code point ranges.

Show model answer

(a) If the software reading the raw bytes assumes the wrong code page (e.g. Latin-1 instead of Windows-1253), each byte will be interpreted as the wrong character, producing garbled text (mojibake) throughout the database — even though none of the underlying data has actually been lost.

(b) Unicode assigns a single, universal code point to every character regardless of language or script, so there is no risk of a future code-page mismatch. Converting to another extended-ASCII code page would only replace one 256-character, region-specific system with another, still leaving the business unable to correctly store, say, both Greek and Chinese customer names in the same database.

(c) U+03B9 falls in the range U+0080–U+07FF, so UTF-8 will use 2 bytes to store it.
