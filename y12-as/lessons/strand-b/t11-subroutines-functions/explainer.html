01

Procedure or function?

Yesterday's procedures package a sequence of statements under a name, so they can be called and reused. A function is the same idea, with one crucial addition: a function always hands a single value back to the place it was called from.

ProcedureFunction
Returns a value?NoYes — exactly one
Defined withPROCEDURE … ENDPROCEDUREFUNCTION … ENDFUNCTION
Called withCALL statementUsed inside an expression — never CALL
BYREF parameters allowed?YesNo — parameters are always by value

That last row matters, and it's easy to forget under exam pressure — we'll come back to it in section 04.

02

Defining and calling a function

A function definition looks like a procedure's, with two differences: RETURNS <data type> appears after the parameter list, stating the type of value the function sends back, and the keyword RETURN is used somewhere in the body to actually send a value back.

pseudocode
FUNCTION Max(Number1 : INTEGER, Number2 : INTEGER) RETURNS INTEGER
   IF Number1 > Number2 THEN
      RETURN Number1
   ELSE
      RETURN Number2
   ENDIF
ENDFUNCTION

A function with no parameters still needs the empty brackets and RETURNS:

pseudocode
FUNCTION RandomDigit() RETURNS INTEGER
   RETURN INT(RAND(10))
ENDFUNCTION
RETURNS vs RETURN RETURNS <type> is part of the function header — it appears once, and states what data type will come back. RETURN <value> is a statement inside the body — it can appear more than once, and each time it runs it sends a specific value back immediately. Mixing these up (or writing ENDPROCEDURE to close a FUNCTION) is a common slip worth checking for in your own code.
03

Functions live inside expressions

A procedure call is a complete statement on its own line, run using CALL. A function call is different: because it produces a value, it's never a statement by itself — it's used as part of a larger expression, wherever a value of that type could go. The keyword CALL is never used for a function.

pseudocode
DECLARE Distance : INTEGER
Distance ← 30
OUTPUT "Penalty Fine = ", Max(10, Distance*2)

Here, Max(10, Distance*2) isn't run in isolation — it's one part of the value list being sent to OUTPUT. The arguments are evaluated first (Distance*2 becomes 60), the function runs and returns a value, and that returned value drops into the expression exactly where the function call was written — as if it had been a literal all along.

Function calls can appear anywhere an expression is allowed: in an assignment (Total ← Max(A, B)), inside a condition (IF Max(A, B) > 100 THEN), or nested inside another call (Max(Max(A, B), C)).

04

Parameters in functions

Function parameters work exactly like the BYVAL parameters from yesterday's lesson — the function receives its own copy of each argument. The difference is that this isn't just the default for functions, it's the only option: the Cambridge pseudocode rules explicitly state that parameters must not be passed by reference to a function.

No BYREF in a function FUNCTION Increment(BYREF Num : INTEGER) RETURNS INTEGER is not valid pseudocode. If a subroutine genuinely needs to modify one of the caller's variables directly, that's a job for a BYREF procedure parameter, not a function — a function's job is to work something out and hand back one value, not to reach out and change the caller's variables as a side effect.

Writing BYVAL explicitly in front of a function's parameters is allowed, but adds nothing — it's already the only mode available:

pseudocode
FUNCTION Increment(BYVAL Num : INTEGER) RETURNS INTEGER
   RETURN Num + 1
ENDFUNCTION

05

RETURN stops the function immediately

When a RETURN statement executes, the function ends there and then — control passes straight back to the calling expression with that value, and any statements written after it in the function are never reached. This lets a function have several possible exit points, one for each case it needs to handle.

pseudocode
FUNCTION Classify(Mark : INTEGER) RETURNS STRING
   IF Mark >= 70 THEN
      RETURN "Distinction"
   ENDIF
   IF Mark >= 50 THEN
      RETURN "Pass"
   ENDIF
   RETURN "Fail"
ENDFUNCTION

Notice there's no ELSE here — it isn't needed. If the first RETURN fires, the function has already ended, so the second IF is never even tested.

06

Local variables inside a function

Just like a procedure, a function can DECLARE its own variables in addition to its parameters, and they follow the same scope rules from yesterday: local to that function, created on each call, and gone once the function returns.

pseudocode
FUNCTION Average(A : INTEGER, B : INTEGER) RETURNS REAL
   DECLARE Total : INTEGER
   Total ← A + B
   RETURN Total / 2
ENDFUNCTION

Total only exists while Average is running. It can't be read from the calling program, and a separate call to Average gets a fresh Total each time — nothing carries over between calls.
