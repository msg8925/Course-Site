E

Exam-style questions

Using the same Classify function from section D, what does this statement print, and why doesn't the first IF fire?

OUTPUT "Grade: ", Classify(49)
Reveal model answer

Prints: Grade: Fail

Mark >= 70 is 49 >= 70, which is FALSE, so the first RETURN is skipped. Mark >= 50 is 49 >= 50, also FALSE, so the second RETURN is skipped too. Execution reaches the final RETURN "Fail", which fires unconditionally if nothing else has already returned.

A student wrote this code and it doesn't work. Identify every mistake, and rewrite it correctly.

PROCEDURE Classify(Mark : INTEGER) RETURNS STRING IF Mark >= 70 THEN RETURN "Distinction" ENDIF RETURN "Fail" ENDPROCEDURE CALL Classify(62)
Reveal model answer

Three mistakes: (1) it's declared as PROCEDURE but has a RETURNS clause and RETURN statements, which only belong on a FUNCTION; (2) it's closed with ENDPROCEDURE instead of ENDFUNCTION; (3) it's invoked with CALL and the returned value is thrown away — a function call must sit inside an expression, such as an OUTPUT or an assignment.

Corrected:

FUNCTION Classify(Mark : INTEGER) RETURNS STRING
   IF Mark >= 70 THEN
      RETURN "Distinction"
   ENDIF
   RETURN "Fail"
ENDFUNCTION

OUTPUT Classify(62) — or assign it, e.g. Grade ← Classify(62).
