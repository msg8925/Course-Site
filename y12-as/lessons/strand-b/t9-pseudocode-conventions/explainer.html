01

Why this matters

You've been reading and writing pseudocode for several lessons now — IF statements, FOR loops, WHILE loops. What's been missing is the rest of the toolkit: how to declare the data an algorithm works with, how to store many values together, and how to package logic into reusable, well-defined pieces. That's what today formalises.

02

Data types & declarations

Before pseudocode uses a variable, it should be declared with a name and a data type:

Pseudocode
DECLARE identifier : datatype
Data typeStoresExample declaration
INTEGERWhole numbersDECLARE age : INTEGER
REALDecimal (floating-point) numbersDECLARE price : REAL
CHARA single characterDECLARE grade : CHAR
STRINGA sequence of charactersDECLARE surname : STRING
BOOLEANTRUE or FALSEDECLARE isValid : BOOLEAN
DATEA calendar dateDECLARE dob : DATE
Choosing a type

Pick the narrowest type that genuinely fits. A whole-number count is INTEGER, not REAL; a yes/no flag is BOOLEAN, not STRING holding "yes" or "no".

03

Constants

A value that's fixed for the whole algorithm — and should never be reassigned — is declared as a constant instead of a variable:

Pseudocode
CONSTANT VAT_RATE = 0.2

Unlike a DECLAREd variable, a constant's value is set once, right there in the declaration, and never changes while the algorithm runs.

04

Arrays

An array stores many values of the same data type under a single identifier, accessed by position (index):

Pseudocode
DECLARE scores : ARRAY[1:10] OF INTEGER
Both bounds are inclusive

ARRAY[1:10] doesn't mean "10 minus 1" — both the lower and upper bound are included, so this array actually holds 10 elements (indices 1 through 10). The number of elements is always upper − lower + 1. This exact same "inclusive at both ends" trap is the one you met with pseudocode's FOR i ← 1 TO N loops.

Array bounds don't have to start at 1 — ARRAY[0:9] OF REAL is equally valid, and also holds 10 elements, indexed 0 through 9.

06

Procedures & functions

Both let you package a piece of logic under a name, so it can be reused without rewriting it. The difference is simple but important:

The key distinction

A FUNCTION always RETURNs exactly one value, so it can be used directly inside an expression. A PROCEDURE performs a task — it might OUTPUT something or change values — but it doesn't hand back a value you can use in an expression.
