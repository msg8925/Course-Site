01

Why files?

Every variable in a program disappears the moment the program ends. A file stores data on disk, so it persists after the program stops — and can be read again the next time the program runs, or by a completely different program.

02

Opening a file

Before reading or writing, a file must be opened, stating which mode it's needed in:

pseudocode
OPENFILE <file identifier> FOR <file mode>
ModeEffect
READOpens an existing file so its contents can be read. Does not change the file.
WRITECreates a new file, or completely overwrites an existing one — all previous data is lost.
APPENDOpens a file so new data can be added to the end, without erasing what's already there.
The file identifier needs quotes OPENFILE "students.txt" FOR READ — examiner reports specifically flag missing quotation marks around the filename as a common, easily-avoided mark loss.
03

Reading from a file

Once a file is open for READ, each call to READFILE reads exactly one line into a variable:

pseudocode
READFILE <file identifier>, <variable>

To read every line in a file, READFILE needs to run inside a loop — one call only ever gets you the next single line.

04

Testing for the end of the file

Since you often don't know in advance how many lines a file contains, the EOF ("end of file") function tells you when to stop:

pseudocode
EOF(<file identifier>)

EOF(...) returns TRUE once there are no more lines left to read, and FALSE otherwise. Combined with a WHILE loop, this is the standard pattern for reading an entire file:

pseudocode
WHILE NOT EOF("students.txt")
   READFILE "students.txt", StudentName
   OUTPUT StudentName
ENDWHILE
Check EOF before reading, not after The condition is tested at the top of the loop, before each READFILE — this is exactly what stops the loop from trying to read one line past the last real line in the file.
05

Writing to a file

Once a file is open for WRITE or APPEND, WRITEFILE adds one piece of data to it:

pseudocode
WRITEFILE <file identifier>, <data>

Remember: WRITE mode erases whatever was already in the file the moment it's opened, before a single WRITEFILE has even run. If the goal is to add to existing content, APPEND is the mode needed instead.

06

Closing a file

pseudocode
CLOSEFILE <file identifier>

Every file that's opened should be closed once the program is finished with it. Forgetting to close a file is one of the most commonly penalised mistakes in file-handling exam answers — make it a habit to write the closing line as soon as you've written the opening one, then fill in the middle.

07

Worked example: filtering a file

This program reads every line of FileA.txt, and copies each one into FileB.txt — except that any blank line is replaced with a row of dashes.

pseudocode
OPENFILE "FileA.txt" FOR READ
OPENFILE "FileB.txt" FOR WRITE
WHILE NOT EOF("FileA.txt")
   READFILE "FileA.txt", LineOfText
   IF LineOfText = "" THEN
      WRITEFILE "FileB.txt", "-------------------------"
   ELSE
      WRITEFILE "FileB.txt", LineOfText
   ENDIF
ENDWHILE
CLOSEFILE "FileA.txt"
CLOSEFILE "FileB.txt"

08

Common mistakes

  • Missing quotes around the filename. OPENFILE StudentData.txt FOR READ is missing the quotation marks a file identifier needs.
  • Using the wrong mode. Opening a file FOR WRITE when the intention was to add to existing content — this silently destroys everything that was there before.
  • Missing EOF check. A loop that reads a fixed number of times instead of checking EOF will crash, or miss data, the moment the file's actual length doesn't match that assumption.
  • Forgetting CLOSEFILE. Every opened file needs a matching close — it's easy to forget once the interesting logic in the middle is done.
