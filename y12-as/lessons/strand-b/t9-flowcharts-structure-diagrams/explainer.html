Algorithm Design: Flowcharts & Structure Diagrams

01

Why this matters

Pseudocode isn't the only way to represent an algorithm. A flowchart shows the same logic — sequence, selection, iteration — as a diagram you can follow with your eyes, tracing a path from start to finish. A structure diagram does something different: it shows how a whole program is broken into smaller pieces, without describing the step-by-step logic inside any of them.

Both are just different views of ideas you already know — today is about learning their visual conventions.

02

Flowchart symbols

Flowcharts use a small set of standard shapes, connected by arrows showing the direction of flow.

Terminal
Start / End
Input/Output
INPUT / OUTPUT
Process
An action or assignment
Decision
A branching condition

Sequence is shown by arrows running one shape to the next. Selection is a decision diamond with two (or more) outgoing arrows, each labelled with the condition's outcome. Iteration is an arrow looping back from later in the chart to an earlier decision point.

04

Structure diagrams

A structure diagram (or structure chart) shows how a program is broken down into modules — the same idea as decomposition, drawn as a hierarchy. The top box is the whole program; the boxes beneath it are the major sub-tasks; each of those can be broken down further still.

Unlike a flowchart, a structure diagram says nothing about the order things happen in, or what logic is inside any box — it only shows what the program is made of. Each box in the finished diagram is a natural candidate to become a PROCEDURE or FUNCTION when the pseudocode is written.

06

Flowcharts vs structure diagrams

FlowchartStructure diagram
ShowsStep-by-step logic of one algorithmHow a program is divided into modules
IncludesDecisions, loops, exact sequence of stepsNo logic, no order — just the module hierarchy
Answers"What happens, in what order?""What is this program made of?"
Common mistake

Don't try to show decisions or loops in a structure diagram, and don't try to show a whole program's module hierarchy in a single flowchart. They answer different questions — use the one that matches what you're being asked to represent.

07

Key takeaways

  • Flowcharts use four core symbols — terminal, input/output, process, decision — connected by arrows showing sequence, selection, and iteration.
  • A structure diagram shows how a program decomposes into modules, as a hierarchy of boxes — it says nothing about order or logic.
  • Each box in a structure diagram is a natural candidate to become a PROCEDURE or FUNCTION.
  • Choose the representation that matches the question: flowcharts for "what happens and in what order," structure diagrams for "what is this program made of."
