E

Exam-style trace

Trace this procedure call fully, giving the final value of P, Q and Mult. Show your working.

PROCEDURE ScaleValues(BYREF A : INTEGER, BYREF B : INTEGER, Factor : INTEGER) A ← A * Factor B ← B * Factor Factor ← 0 ENDPROCEDURE DECLARE P : INTEGER DECLARE Q : INTEGER DECLARE Mult : INTEGER P ← 4 Q ← 5 Mult ← 3 CALL ScaleValues(P, Q, Mult) OUTPUT P, Q, Mult
Reveal model answer

P = 12, Q = 15, Mult = 3.

A and B are BYREF, so they're aliases for P and Q. A ← A * Factor sets P to 4 × 3 = 12, and B ← B * Factor sets Q to 5 × 3 = 15. Factor is BYVAL — a local copy of Mult's value — so Factor ← 0 only changes that copy. Mult itself, back in the calling program, is never touched and stays 3.

Explain, in terms of scope and parameter passing, why Mult still equals 3 at the end even though Factor is set to 0 inside the procedure.

Reveal model answer

Factor is a BYVAL parameter, so it is a local variable that belongs only to ScaleValues, holding its own independent copy of the value that was in Mult at the moment of the call. Setting Factor ← 0 changes that local copy only. When the procedure ends, Factor — and its value of 0 — is destroyed along with it. Mult, declared in the main program, is a separate variable in a separate scope and was never linked to Factor, so it is completely unaffected.
