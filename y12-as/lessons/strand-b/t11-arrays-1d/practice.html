E

Exam-style questions

A student declares DECLARE Temperatures : ARRAY[1:7] OF REAL to store one temperature reading per day of a week, then writes FOR Day ← 0 TO 6 to populate it via user input, using Day directly as the index. Identify the bug, and explain how to fix it in two different ways.

Reveal model answer

The bug: the array is declared with bounds [1:7], but the loop runs Day from 0 to 6 and uses it directly as the index — so Temperatures[0] is accessed on the first iteration, which is outside the array's declared bounds (an invalid index), and Temperatures[7], a valid index, is never populated at all.

Fix 1: change the loop to FOR Day ← 1 TO 7 so it matches the array's declared bounds exactly.

Fix 2: keep the loop as FOR Day ← 0 TO 6, but declare the array to match it instead: DECLARE Temperatures : ARRAY[0:6] OF REAL.

Explain why a linear search that always finished checking every element — even after finding a match — would still give a correct result, but would not be considered good style. What would need to change to make it stop early?

Reveal model answer

It would still give a correct result because once a matching index has been identified, checking further elements doesn't change that answer — the first match found is still the right answer to return. However, it wastes time checking elements that can no longer affect the outcome, which matters more the larger the array is (searching a million-element array all the way to the end when the match was at index 1 is needlessly slow).

To stop early, the function needs a mechanism that ends execution the moment a match is found — exactly what RETURN provides inside a function. Without a function (for example, inside a plain procedure or the main program), the same early exit would need a boolean flag checked by the loop's condition, since a bare FOR loop has no built-in way to stop before its final iteration.
