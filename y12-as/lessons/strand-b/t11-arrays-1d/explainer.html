01

Why arrays?

Imagine storing five test scores. Without arrays, you'd need five separate variables — Score1, Score2, Score3, Score4, Score5 — and any loop that wanted to process "all the scores" would have no clean way to do it; you'd have to write out each variable by name.

An array solves this: it's a single named structure holding many values of the same data type, each one accessible by its position — its index. This means a loop can visit every element just by counting through the indices.

02

Declaring a 1D array

pseudocode
DECLARE <identifier> : ARRAY[<lower>:<upper>] OF <data type>

The <lower> and <upper> bounds are both fixed when the array is declared, and both are inclusive — every whole number from the lower bound to the upper bound, including both ends, is a valid index.

pseudocode
DECLARE Scores : ARRAY[1:5] OF INTEGER

This declares Scores as an array of exactly 5 integers, indexed 1, 2, 3, 4, 5.

Why state the lower bound explicitly? Different languages and systems default to a lower bound of 0 or 1 — stating it explicitly in the declaration removes any doubt. Cambridge pseudocode generally uses a lower bound of 1, but 0 is equally valid pseudocode if a problem calls for it (a day-of-week array indexed 0 to 6, say).
DeclarationValid indicesNumber of elements
ARRAY[1:5]1, 2, 3, 4, 55
ARRAY[0:6]0, 1, 2, 3, 4, 5, 67
The element count isn't just "the upper bound" For ARRAY[0:6], there are 7 elements, not 6 — the formula is upper − lower + 1. Forgetting the + 1 is a very easy mistake to make when the lower bound isn't 1.
03

Accessing and assigning elements

A specific element is referred to by writing the array's name followed by the index in square brackets. This works exactly like any other variable — it can appear on the left of an assignment, or be read as part of an expression.

pseudocode
Scores[1] ← 95
Scores[2] ← 82
OUTPUT Scores[1]          // outputs 95
OUTPUT Scores[1] + Scores[2]   // outputs 177
04

Populating an array with a loop

Because indices are consecutive whole numbers, a FOR loop is a natural way to fill every element of an array — the loop counter is the index.

pseudocode
DECLARE Scores : ARRAY[1:5] OF INTEGER
FOR Index ← 1 TO 5
   Scores[Index] ← Index * 10
NEXT Index

05

Searching an array

A linear search checks each element in turn, starting from the lower bound, until either a match is found or every element has been checked. Writing it as a function reuses exactly what you already know about RETURN ending execution immediately:

pseudocode
FUNCTION LinearSearch(Scores : ARRAY[1:5] OF INTEGER, Target : INTEGER) RETURNS INTEGER
   FOR Index ← 1 TO 5
      IF Scores[Index] = Target THEN
         RETURN Index
      ENDIF
   NEXT Index
   RETURN -1
ENDFUNCTION

The moment a match is found, RETURN Index ends the function immediately — the remaining elements are never even checked. If the loop finishes without ever matching, RETURN -1 signals "not found" (a value that could never be a valid index).

06

Bounds and common mistakes

  • Arrays are fixed size. Once DECLAREd with bounds [1:5], that array always holds exactly 5 elements — there's no way to add a sixth without declaring a new, bigger array.
  • Out-of-bounds access is invalid. For ARRAY[1:5], both Scores[0] and Scores[6] are outside the declared bounds and must not be used.
  • Every element shares one data type. An array declared OF INTEGER cannot hold a STRING in any of its elements.
Off-by-one errors The single most common array bug is a loop that runs one iteration too many or too few — for example, writing FOR Index ← 1 TO 4 against an array declared [1:5], which silently skips the last element. Always check a loop's range against the array's actual declared bounds, not against habit.
