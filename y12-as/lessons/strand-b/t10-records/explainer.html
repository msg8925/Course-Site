Records

An array holds many values of the same type. A record holds several values of different types, all describing one thing.

01

Why records?

An array is excellent for many values of the same type — five test scores, ten temperatures. But what about one student's name (STRING), age (INTEGER), and grade (CHAR) — three different types, all describing the same student? An array can't hold mixed types. A record can: it groups several named fields, each with its own data type, under one identifier.

02

Declaring a record type

pseudocode
TYPE <identifier>
   DECLARE <fieldname> : <data type>
   DECLARE <fieldname> : <data type>
   ...
ENDTYPE

This defines the shape of the record — its name and fields — but doesn't create any actual data yet, just as declaring a procedure doesn't run it.

pseudocode
TYPE StudentRecord
   DECLARE Name : STRING
   DECLARE Age : INTEGER
   DECLARE Grade : CHAR
ENDTYPE
03

Declaring a variable and using dot notation

Once a record type exists, it can be used exactly like any built-in type — INTEGER, STRING — when declaring a variable:

pseudocode
DECLARE Student1 : StudentRecord

To access or assign one field of a record variable, write the variable's name, a dot, then the field name:

pseudocode
Student1.Name ← "Amara"
Student1.Age ← 16
Student1.Grade ← 'B'
OUTPUT Student1.Name, " is ", Student1.Age
The dot means "belongs to" Read Student1.Age as "the Age field that belongs to Student1." Every record variable gets its own independent copy of every field — a second Student2 : StudentRecord has a completely separate Student2.Age.
04

Arrays of records

Records and arrays combine naturally: an array of records stores many records of the same type, each accessible by index — a whole class of students, say, each with a name, age and grade.

pseudocode
DECLARE Students : ARRAY[1:3] OF StudentRecord

To reach a specific field of a specific student, combine array indexing with dot notation — the index comes right after the array name, and the field name after that:

pseudocode
Students[1].Name ← "Amara"
Students[1].Age ← 16
Students[1].Grade ← 'B'

06

Traversing an array of records

A single loop is enough to visit every record in the array (unlike a 2D array of plain values, this doesn't need nesting — each index already refers to one whole record, fields and all).

pseudocode
DECLARE Total : INTEGER
Total ← 0
FOR Index ← 1 TO 3
   Total ← Total + Students[Index].Age
NEXT Index
DECLARE AverageAge : REAL
AverageAge ← Total / 3

07

Common mistakes

  • Forgetting the dot notation. Writing Students[1]Age or trying to treat Students[1] as if it were a single value, rather than a whole record with fields inside it.
  • Confusing the type definition with a variable. TYPE StudentRecord ... ENDTYPE only defines the shape — it does not create any actual student. A separate DECLARE is always needed to make a usable variable of that type.
  • Assigning the wrong data type to a field. Every field keeps the data type it was declared with — assigning a STRING to a field declared INTEGER is just as invalid as it would be for an ordinary variable.
A record variable is not a record type StudentRecord is the type — the blueprint. Student1 is a variable of that type — one actual student following that blueprint. You can declare as many variables of the same record type as you need, each with its own independent set of field values.
