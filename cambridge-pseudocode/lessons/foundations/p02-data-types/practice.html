Task D1 · Debugging
Fix the student recordcheckable

This program contains three mistakes with data types and literals. Paste it into the editor and fix it until it runs with no errors. Read every line: one mistake breaks the Cambridge rules even if the editor happens to accept it.

buggy code
DECLARE StudentName : STRING
DECLARE Age : INTEGER
DECLARE Height : REAL
DECLARE Initial : CHAR
StudentName ← Sam
Age ← "15"
Height ← 1.62
Initial ← "S"
OUTPUT StudentName, " is ", Age, " years old and ", Height, "m tall"

What does your fixed program output?

Show the three mistakes
  • StudentName ← Sam: a STRING literal needs double quotes, "Sam". Without them, Sam looks like an undeclared variable.
  • Age ← "15": the quotes make it a STRING; an INTEGER needs 15.
  • Initial ← "S": a CHAR literal uses single quotes, 'S'.
Task D2 · Constants
The online shopcheckable
  1. Copy the starter code into the editor. Complete the missing line so that TotalCost is the cost of the items plus the delivery charge. Run it.
  2. The shop raises its delivery charge to 6.0. Change one line so the program uses the new charge, and run it again.
  3. Finally, add the line DeliveryCharge ← 1.0 just before the OUTPUT line and run it. Read the error message: this is the constant protecting itself. Delete the line again.
starter code
CONSTANT DeliveryCharge ← 4.5
DECLARE ItemPrice : REAL
DECLARE Quantity : INTEGER
DECLARE TotalCost : REAL
ItemPrice ← 12.5
Quantity ← 3
// complete this line: TotalCost ← ...

OUTPUT "Total: ", TotalCost

What did your program output in step 1, with the original delivery charge?

Show a model solution
pseudocode
TotalCost ← ItemPrice * Quantity + DeliveryCharge

12.5 × 3 = 37.5, plus 4.5 = 42. For step 2, only the CONSTANT line changes, and the total becomes 43.5. That is the point of a constant: one place to update.

Task D3 · Extension
Write your own: a library book

Write a program from scratch that stores details of a library book and outputs them. It must include:

  • a constant LoanDays with the value 14;
  • variables for the title (STRING), number of pages (INTEGER), price (REAL), shelf letter (CHAR) and whether it is on loan (BOOLEAN);
  • an OUTPUT line for the title, number of pages, price and shelf letter, and one for the loan period.
Show a model solution
pseudocode
// Stores and displays details of a library book
CONSTANT LoanDays ← 14
DECLARE Title : STRING
DECLARE Pages : INTEGER
DECLARE Price : REAL
DECLARE Shelf : CHAR
DECLARE OnLoan : BOOLEAN
Title ← "The Hidden Code"
Pages ← 320
Price ← 9.99
Shelf ← 'K'
OnLoan ← FALSE
OUTPUT Title, ": ", Pages, " pages, price ", Price, ", shelf ", Shelf
OUTPUT "Loan period: ", LoanDays, " days"

E2. A program calculates the tax on a sale. Explain why the tax rate should be stored as a constant rather than a variable.[2]
Show mark scheme

Any two points, one mark each:

  • The tax rate does not change while the program is running.
  • It cannot be changed accidentally by another part of the program.
  • If the rate changes in future, it only needs updating in one place.
  • The name makes the code easier to read than a number on its own.
E3. Write pseudocode to declare: a constant MaxPlayers with the value 4; a variable PlayerName to store a player’s name; a variable HighScore to store a whole-number score.[3]
Show mark scheme
model answer
CONSTANT MaxPlayers ← 4
DECLARE PlayerName : STRING
DECLARE HighScore : INTEGER
