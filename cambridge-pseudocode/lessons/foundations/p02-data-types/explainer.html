Data Types, Variables & Constants

01

What is a variable?

A variable is a named location in memory that stores one value, and that value can change while the program runs.

Think of a set of labelled storage boxes. The label on the front is the identifier (such as Score), and the box holds exactly one thing at a time. Put something new in, and whatever was there before is thrown away. You met this in Topic 1, when Price changed from 4 to 5.

Each box is also a particular shape. A box for whole numbers can’t hold a sentence, and a box for a single letter can’t hold a whole name. That shape is the variable’s data type.

Key ideaEvery variable has three things: an identifier (its name), a data type (what kind of value it holds), and a value (what it holds right now).
02

The data types

Cambridge pseudocode has five basic data types that both IGCSE and AS use. The literal column shows how a value of each type is written in code.

Data typeHoldsLiteral examplesTypical use
INTEGERA whole number, positive, negative or zero5, -3, 0Counts, ages, scores
REALA number that can have a fractional part4.7, 0.3, -4.0, 0.0Prices, measurements, averages
CHARExactly one character'x', 'C', '@'A grade letter, a Y/N answer
STRINGZero or more characters"Hello", "A", ""Names, messages, codes
BOOLEANOne of two valuesTRUE, FALSEYes/no facts, flags

Writing literals correctly

  • REAL values always have at least one digit on each side of the decimal point. Write 0.5, never .5, and 4.0 when you mean a REAL four.
  • CHAR values go in single quotes and hold exactly one character.
  • STRING values go in double quotes. "" is the empty string: a string with no characters in it.
  • BOOLEAN values are written TRUE and FALSE with no quotes. "TRUE" in quotes is a STRING that just happens to spell a word.
AS (9618) only: DATEAS pseudocode adds a sixth type, DATE, for a valid calendar date. Date values are normally written in the format dd/mm/yyyy, e.g. 23/06/1912. IGCSE does not use DATE.

Looks can deceive

The same characters can be different types depending on how they are written: 7 is an INTEGER, 7.0 is a REAL, '7' is a CHAR and "7" is a STRING. Only the first two can be used in arithmetic.

Phone numbers are stringsA phone number such as "0812345678" is made of digits, but it is a STRING. You never do arithmetic on it, and storing it as an INTEGER would lose the leading zero. The same goes for product codes, postcodes and ID numbers with letters or leading zeros.

03

Declaring variables

Before a variable can be used, it is declared: the program is told its identifier and its data type. The format is:

syntax
DECLARE <identifier> : <data type>

For example:

pseudocode
DECLARE Counter : INTEGER
DECLARE TotalToPay : REAL
DECLARE GameOver : BOOLEAN

Declaring a variable creates the box but puts nothing in it. Give it a value with an assignment before you use it; the first assignment is called initialising the variable:

pseudocode
DECLARE Counter : INTEGER
Counter ← 0          // initialise before use
Good habitsPut all your declarations at the top of the program, one per line, each with a meaningful PascalCase identifier (Topic 1). A reader can then see every variable and its type at a glance.
04

Types must match

The value you assign must be the same data type as the variable. A box for whole numbers can’t take "fifteen". Pseudocode Pro enforces this: a mismatch is an error, and the program will not run.

Pseudocode Pro allows two safe exceptions, because no information is lost:

  • an INTEGER value into a REAL variable (5 becomes 5.0);
  • a CHAR value into a STRING variable (a one-character string).

In exam answers, match the type exactly, e.g. Total ← 0.0 for a REAL, so there is no room for doubt.

05

Constants

A constant is a named value that cannot change while the program runs. It is declared once, with its value, and the program then uses its name.

pseudocode
CONSTANT HourlyRate ← 6.50
CONSTANT DefaultText ← "N/A"
IGCSE (0478) and AS (9618) write constants differentlyIGCSE uses the arrow: CONSTANT HourlyRate ← 6.50. AS uses an equals sign: CONSTANT HourlyRate = 6.50. Use your own course’s form in exams. Pseudocode Pro checks for your syllabus’s form, and the switch at the top of this page changes the code examples to match.

Rules

  • The value must be a literal, such as 6.50 or "N/A". It can never be a variable, another constant or a calculation like Rate * 2.
  • A constant cannot be given a new value later. HourlyRate ← 7.00 anywhere in the program is an error.
  • A constant has no DECLARE line and no data type written: the type comes from the literal.

Why use a constant?

  • Readability: Pay ← Hours * HourlyRate explains itself; Pay ← Hours * 6.50 leaves the reader guessing what 6.50 is.
  • Easy to update: if the rate changes, you edit one line at the top rather than hunting for every 6.50.
  • Safety: the value can’t be changed by mistake somewhere else in the program.

Naming: the Cambridge guides name constants in PascalCase, like variables (HourlyRate). You will also see ALL-CAPS names such as PI in other resources. Both follow the identifier rules; this course uses PascalCase.

06

Putting it together

This cinema-booking program uses a constant and all five data types.

pseudocodeCinema booking
// Works out the cost of a cinema booking
CONSTANT TicketPrice ← 8.50
DECLARE FilmTitle : STRING
DECLARE Tickets : INTEGER
DECLARE SeatRow : CHAR
DECLARE IsMember : BOOLEAN
DECLARE TotalCost : REAL
FilmTitle ← "Space Race"
Tickets ← 3
SeatRow ← 'F'
IsMember ← FALSE
TotalCost ← Tickets * TicketPrice
OUTPUT "Film: ", FilmTitle
OUTPUT Tickets, " tickets in row ", SeatRow
OUTPUT "Total: ", TotalCost

It outputs:

output
Film: Space Race
3 tickets in row F
Total: 25.5
ItemTypeWhy
TicketPriceconstant (REAL)Fixed for the whole program, and a price needs a fractional part.
FilmTitleSTRINGSeveral characters of text.
TicketsINTEGERYou can’t buy half a ticket.
SeatRowCHARExactly one letter.
IsMemberBOOLEANEither a member or not. Later topics use this to decide on a discount.
TotalCostREALINTEGER × REAL gives a REAL: 3 × 8.50 = 25.5.
07

Exam tips

  • “State the most appropriate data type” questions are common. Give the exact keyword (REAL, not “decimal” or “float”).
  • Money and measurements are REAL. Counts of whole things are INTEGER.
  • Anything made of digits that you never calculate with (phone numbers, ID codes) is a STRING.
  • Write every declaration as DECLARE Name : TYPE with the colon.
  • Use your course’s constant syntax: ← for IGCSE, = for AS. A constant’s value must be a literal.
  • Quotes matter: single for CHAR, double for STRING, none for BOOLEAN and numbers.
