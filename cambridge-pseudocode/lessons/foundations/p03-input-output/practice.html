Task D1 · Debugging
Fix the birthday programcheckable

This program has three mistakes. Fix them, then run it and enter Sam and 15. One mistake is about data types, so think about what Age + 1 needs.

buggy code
DECLARE Name : STRING
DECLARE Age : STRING
OUTPUT "Enter your name:"
INPUT "Name"
OUTPUT "Enter your age:"
INPUT Age
OUTPUT "Hello " Name, ", next year you will be ", Age + 1

What is the last line your fixed program outputs?

Show the three mistakes
  • DECLARE Age : STRING should be INTEGER: the program adds 1 to it.
  • INPUT "Name" should be INPUT Name: INPUT takes a variable name, not a string.
  • A comma is missing between "Hello " and Name.
Task D2 · Write it
Fahrenheit to Celsiuscheckable

The explainer converted Celsius to Fahrenheit. Write the reverse program from scratch. It should prompt for a temperature in Fahrenheit, input it, calculate the Celsius value with the formula below, and output the answer with a message.

formula
Celsius ← (Fahrenheit - 32) * 5 / 9
  1. Test it with 32. You should get 0 (water freezes).
  2. Test it with 212.
  3. Run it once more and type hot instead of a number. What does Pseudocode Pro do? That is why the validation topic comes later in the course.

What Celsius value does your program calculate for 212? (just the number)

Show a model solution
pseudocode
// Converts a temperature from Fahrenheit to Celsius
DECLARE Fahrenheit : REAL
DECLARE Celsius : REAL
OUTPUT "Enter a temperature in Fahrenheit:"
INPUT Fahrenheit
Celsius ← (Fahrenheit - 32) * 5 / 9
OUTPUT Fahrenheit, " F is ", Celsius, " C"
Task D3 · Extension
Write your own: a receipt line

Plan first: fill in an input / process / output table for a program that asks for an item’s name, its price and the quantity bought, and outputs one receipt line such as:

example output
3 x Notebook = 7.5

Then write the program in Pseudocode Pro, with a clear prompt before each input. Test it with at least two different sets of inputs.

Show a model solution
pseudocode
// Outputs one line of a receipt
DECLARE ItemName : STRING
DECLARE Price : REAL
DECLARE Quantity : INTEGER
DECLARE LineTotal : REAL
OUTPUT "Enter the item name:"
INPUT ItemName
OUTPUT "Enter the price of one item:"
INPUT Price
OUTPUT "Enter the quantity:"
INPUT Quantity
LineTotal ← Price * Quantity
OUTPUT Quantity, " x ", ItemName, " = ", LineTotal

IPO: input the item name, price and quantity; process LineTotal = Price × Quantity; output the receipt line.

E1. Write pseudocode that asks the user to input two whole numbers, then outputs their sum with a suitable message.[4]
Show mark scheme
model answer
DECLARE Number1 : INTEGER
DECLARE Number2 : INTEGER
OUTPUT "Enter the first number:"
INPUT Number1
OUTPUT "Enter the second number:"
INPUT Number2
OUTPUT "The sum is ", Number1 + Number2

One mark each:

  • Both variables declared as INTEGER.
  • A prompt output before each input.
  • Two separate INPUT statements, each into a variable.
  • Output of the sum with a message.
E2. Explain why a program should output a prompt before each INPUT statement.[2]

  • INPUT on its own gives the user no message: the program just waits. [1]
  • The prompt tells the user what data to enter / in what format, so they enter valid data. [1]
