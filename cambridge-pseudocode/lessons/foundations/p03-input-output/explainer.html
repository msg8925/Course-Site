01

Input, process, output

So far, every value in our programs was typed into the code itself. That program gives the same result every time it runs. Real programs work with data from the user, so they can give a different result each time.

Almost every program follows the same pattern, often called IPO:

StageWhat happensCash machine example
InputData comes into the program, usually typed by the user.You type the amount to withdraw.
ProcessThe program works with the data: calculations and decisions.It checks your balance and subtracts the amount.
OutputResults go back out, usually displayed on screen.It shows your new balance.
Key ideaINPUT brings data into the program and stores it in a variable. OUTPUT sends data out to the screen. Everything in between is processing.
02

OUTPUT in detail

You have used OUTPUT since Topic 1. The format is:

syntax
OUTPUT <value(s)>

The values can be literals, variables, or calculations, and several values are separated by commas:

pseudocodeLives = 3, Score = 42
OUTPUT "Game over"
OUTPUT Score
OUTPUT "You have ", Lives, " lives left"
OUTPUT "Double score: ", Score * 2
output
Game over
42
You have 3 lives left
Double score: 84

Three rules to remember

  • Each OUTPUT statement starts a new line.
  • The values are joined with no spaces added. Put any spaces you need inside the quotes, e.g. "You have ".
  • Quotes decide what is printed. OUTPUT Score prints the value, 42. OUTPUT "Score" prints the word Score.
The three most common OUTPUT mistakesA missing comma between items ("Total: " Total); a missing space inside the quotes, giving Total:10; and a variable name put in quotes, which prints its name instead of its value.

03

INPUT

INPUT lets the user type a value while the program runs. The value is stored in a variable:

syntax
INPUT <identifier>

When the program reaches INPUT, it pauses and waits. Whatever the user types is stored in the variable, replacing any value it held before. Then the program carries on with the next line.

  • The variable must be declared first, like any other (Topic 2).
  • INPUT is followed by a variable name only, with no quotes. INPUT "Age" is wrong.
  • One INPUT statement collects one value. To collect two values, use two INPUT statements.

Always prompt first

In Cambridge pseudocode, INPUT has no message of its own. Without one, the user sees the program stop, with no idea what it wants. So always OUTPUT a prompt on the line before:

pseudocode
DECLARE Age : INTEGER
OUTPUT "How old are you?"     // the prompt
INPUT Age                    // waits for the user
Good promptsA good prompt says exactly what to type and in what form: "Enter the price in dollars, e.g. 4.99:" is clearer than "Price?".
IGCSE (0478) and AS (9618)INPUT and OUTPUT are written the same way in both courses.
04

Input and data types

The value typed in is stored as the data type of the variable. That is why choosing the right type (Topic 2) matters so much here:

  • If you will calculate with the value, input it into an INTEGER or REAL variable.
  • If it is text, or digits you never calculate with (a phone number), use a STRING.
  • If the user types something the variable can’t hold, such as ten into an INTEGER, the program can’t store it. You will see what Pseudocode Pro does in the practice tasks. Later, in the validation topic, you will learn to check input before using it.

05

A complete program

This program converts a temperature from Celsius to Fahrenheit. Before writing code, it helps to plan it as input, process and output:

StageFor this program
InputA temperature in Celsius (a REAL, since it may have a decimal part)
ProcessFahrenheit = Celsius × 9 ÷ 5 + 32
OutputBoth temperatures, with a message
pseudocodeTemperature converter
// Converts a temperature from Celsius to Fahrenheit
DECLARE Celsius : REAL
DECLARE Fahrenheit : REAL
OUTPUT "Enter a temperature in Celsius:"
INPUT Celsius
Fahrenheit ← Celsius * 9 / 5 + 32
OUTPUT Celsius, " C is ", Fahrenheit, " F"

If the user types 37.5 when asked, the program outputs:

output
Enter a temperature in Celsius:
37.5 C is 99.5 F

Line by line: the prompt appears; the program waits and stores 37.5 in Celsius; it calculates 37.5 × 9 ÷ 5 + 32 = 99.5 and stores it in Fahrenheit; then it outputs the result, with spaces inside the quotes so the words don’t run together.

Test with different inputsA program that uses input should be tried with several values. Here, 100 should give 212 and 0 should give 32, which are water’s boiling and freezing points. If those are right, the formula is probably right.
06

Exam tips

  • Questions often say “Write pseudocode to input… and output…”. Plan the input, process and output before writing.
  • Put a meaningful prompt before every INPUT. Many mark schemes give credit for it.
  • INPUT takes a variable name only: INPUT Age, never INPUT "Age".
  • Separate OUTPUT items with commas, and put spaces inside the quotes.
  • Declare input variables with the right type: numbers you calculate with as INTEGER or REAL.
