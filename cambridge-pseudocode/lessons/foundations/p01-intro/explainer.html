01

What is pseudocode?

Pseudocode is a way of writing an algorithm that looks like program code but is not tied to any one real programming language. It is written for people to read, so it keeps the structure of a program (steps, decisions, loops) without the fussy details of Python, Java or Visual Basic.

Think of it like a recipe written in plain, structured steps. A chef in Bangkok and a chef in London can both follow “boil 500 ml of water, then add the pasta” even though their kitchens have different cookers. Pseudocode does the same job for programmers: anyone can turn it into their own language.

Why Cambridge uses its own pseudocode

Students around the world learn different languages, so Cambridge exams ask for algorithms in a standard pseudocode. It has a fixed set of keywords and layout rules, which means an examiner can read your answer quickly and fairly, whichever language you use in class.

Key ideaNormally pseudocode cannot be run by a computer. It is a design tool. Pseudocode Pro is special: it understands Cambridge pseudocode well enough to run it, so you can test your answers before the exam.
02

Anatomy of a program

Here is a complete, small program. The colours show the different kinds of “word” it is made from.

KEYWORDIdentifierDATATYPEoperator ←"literal"// comment
pseudocodeWelcome program
// Greets the user and shows the year
DECLARE UserName : STRING
DECLARE Year : INTEGER
UserName ← "Alex"
Year ← 2026
OUTPUT "Welcome, ", UserName
OUTPUT "The year is ", Year
PartWhat it is
KeywordA word with a fixed meaning in the language, such as DECLARE or OUTPUT. Always written in UPPER CASE.
IdentifierA name you choose for something, such as a variable. Here: UserName and Year.
Data typeThe kind of data an identifier holds, e.g. STRING for text or INTEGER for whole numbers. (Next lesson covers these in full.)
Assignment ←Puts a value into a variable. Read Year ← 2026 as “Year becomes 2026”.
LiteralA fixed value typed straight into the code: "Alex" or 2026.
CommentA note for humans, starting with //. The computer ignores it.

When this program runs it outputs:

output
Welcome, Alex
The year is 2026

Notice that OUTPUT can display several items separated by commas. They are joined together with no extra spaces added, which is why "Welcome, " has a space before its closing quote.

Why the arrow?

In maths, = means “is equal to”, which is a statement of fact. Assignment is an action: take the value on the right and store it in the variable on the left. The arrow shows the direction the data moves. So Score ← Score + 10 makes perfect sense (“Score becomes its old value plus 10”), even though Score = Score + 10 would be impossible in maths.

Indentation

You will meet IF statements and loops in later lessons. The lines inside them are indented by four spaces so the reader can see at a glance which lines belong together:

pseudocodepreview of a later topic
IF Score > 50 THEN
    OUTPUT "Pass"        // indented 4 spaces
ENDIF

04

Naming things: identifiers

An identifier must follow these rules, or the program is wrong:

  • It may only contain letters (A–Z, a–z), digits (0–9) and the underscore _.
  • It must start with a letter.
  • It cannot contain spaces.
  • It cannot be a keyword, so a variable called OUTPUT is not allowed.

It should also follow good style, which examiners reward because it makes code readable:

  • Use a meaningful name: TotalCost, not x.
  • Use PascalCase: start each word with a capital, e.g. NumberOfStudents.
  • Identifiers are treated as case-insensitive, so never use Total and TOTAL as two different variables.

Sequence: one line at a time

A program runs from the top line to the bottom line, in order. This is called sequence. A variable holds exactly one value at a time: assigning a new value replaces the old one completely.

06

Using Pseudocode Pro

Pseudocode Pro is a free website that runs Cambridge pseudocode in your browser. Use it to test every program you write in this course.

  1. Open the editor at pseudocode.pro/editor. You do not need an account.
  2. Choose your syllabus from the Syllabus menu: “Cambridge IGCSE 0478” or “Cambridge A-Level 9618”. The editor then checks your code against the rules for your course.
  3. Type the arrow by typing <- (less-than, then hyphen). The editor turns it into ← automatically. You can also press Ctrl + Shift + <.
  4. Run your code with the triangular play button. Under Run & Options you can change the execution mode: “Run on click” is the calmest choice while you are learning, because “Live” re-runs after every key you type.
  5. Read the error panel. It says No errors ✅ when your code is valid. If something is wrong it shows a message and the line number, which you can click to jump to the mistake.
  6. Make a trace table with the Create Trace Table button. The table is only generated while that window is open, so open it first and then run the program. You will use this a lot in later topics.
  7. Save your work with Download, which saves a .pseudo file. The editor also autosaves in your browser, but that copy is lost in a private window or if browser data is cleared.
Pseudocode Pro is strict about data typesIt checks that every variable is declared with DECLARE and that you only store the right kind of value in it. That is why the programs on this page start with DECLARE lines. You will learn exactly how these work next lesson; for now, copy them as shown.

07

Exam tips

  • Write keywords in capitals and use ← for assignment. Examiners read hundreds of scripts, and clear, standard code is easier to credit.
  • Choose meaningful identifiers. If a question has already named a variable (e.g. Total), use that exact name.
  • Indent the contents of every IF, CASE and loop. It helps you spot missing ENDIFs and helps the examiner follow your logic.
  • A comment can explain a tricky step, but you do not need one on every line.
  • When asked what a program outputs, work through it line by line and keep track of every variable, just like the tracer above.
